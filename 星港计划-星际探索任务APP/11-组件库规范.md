## 一、这套东西解决什么

手摆板的三个问题不是不好看，而是同一件东西有多个版本：

| 问题 | 实测 | 后果 |
|---|---|---|
| 同一元素多个尺寸 | 任务状态按钮出现 113 / 117 / 121 / 124 四种宽度；按钮高有 30 / 40 / 45 三种 | 拼界面每处都要手动对齐 |
| 同一语义多个色值 | 红有 #ff0d00 与 #ff0000；黄有 #ffe100 与 #ffd000；灰阶多达 17 个 | 改一次主色要翻遍全稿 |
| 重复绘制 | 任务卡画两遍（823:94 / 874:374）；分段器画两套（散装 + 成组） | 改一处忘一处 |

标准化后：33 个令牌 + 25 个组件集全部由变量驱动，可换肤、可复用、出图统一。

## 四、尺寸标准化对照

| 原值 | 标准值 | 出现次数 | 说明 |
|---|---|---|---|
| 361（宽） | **358** | 6 | 与线框稿 `content/w` 统一（390 − 16×2） |
| 335（知识卡宽） | **358** | 1 | 与任务卡对齐，两张卡同宽 |
| 30（高） | **32** | 8 | 统一到 `h/sm` |
| 45（高） | **48** | 6 | 统一到 `h/lg` |
| 61（按钮宽） | **112** | 6 | 收进 `Btn/Action` 的 md 档 |
| 113 / 117 / 121 / 124 | **120** | 4 类 | 同一「任务状态按钮」的四种宽度 → 一个 |
| 79 / 81 / 106 | **80** | 3 类 | 芯片宽度 → 一个 |
| 115 + 间距 3 | **114 + 间距 4** | 6 | 2+114+4+114+4+114+2 = 358 |
| 227（卡内进度条） | **326** | 2 | 卡片内宽 − 左右各 16 |
| 59（卡内视觉区高） | **56** | 2 | 落栅格 |

均为 1–5 px 级微调，不改观感；想保留某个原值，改组件里的尺寸即可（令牌是变量，组件尺寸是固定值，不冲突）。

## 五、用法要点

1. 从 Assets 拖组件 → 右栏改变体属性 → 有文字属性的改文案。
2. 改色只动 `SP/Color` 变量，改尺寸只动 `SP/Metric` 变量；不要手动改实例填充，也不要再从手摆板复制矩形拼界面（会带回 361/30/45 离群值）。
3. 新组件先复用现有 25 个；确实需要新的，按同一套令牌做。
4. 拼页面：内容宽 358，左右安全边距 16。
5. 有文字属性的组件：`Btn/Action`（Label）、`Card/Knowledge`（Body、Code）、`Bar/Nav`（Title）、`Field/Input`（Text）、`Block/Ring`（Time）、`Card/Event`（Title、Body）、`Card/Program`（Title）、`Card/Facility`（Name）、`Panel/Dialog`（Title、Body）、`Toast`（Text）、`Card/Task`（Time）。
6. 其余组件文案由变体决定，不加文字属性——跨变体共享的文字属性只有一个值，给任一变体赋值会同步到全部变体（实测：四个 chip 全变成「待确认」，两个状态按钮全变成「终止」）。

## 六、矩形体积感

用户声明的六条原则：

| # | 原则 | 落地 |
|---|---|---|
| 1 | 尽量保持视觉对齐 | 组件从手摆节点直接归组，`node reparent` 保留画布坐标 |
| 2 | 数字占位长度固定 | 计时/编号/数值类文字框宽度不随内容变化，避免跳动 |
| 3 | 内部元素与外框边距统一 | 同一组件内边距取齐 |
| 4 | 单个组件内增加层次 | 计划卡 / 设施卡的强调文字用 24（正文 12） |
| 5 | 分段选择器配色按手摆板 | 选中 `#c8c8c8` 浅底黑字 / 未选中 `#151515` 深底灰字 |
| 6 | 每个矩形外框要有无模糊投影 + 内阴影 | 见下方配方 |

效果配方（提取自手摆板，blur 一律为 0）：

| 用途 | 配方 |
|---|---|
| 容器 / 面板（`#2c2c2c` + 描边） | `DROP` x4 y4 `#393939` |
| 凸起块（`#c8c8c8`） | `INNER` −2,−2 `#969696` + `INNER` 2,2 `#d6d6d6` + `DROP` 2,2 `#393939` |
| 中灰块（`#666666`） | `INNER` −2,−2 `#737373` + `INNER` 2,2 `#757575`（+ 可选 `DROP` 2,2） |
| 凹下块（`#151515`） | `INNER` 2,2 `#000000` |
| 白进度条填充（`#ffffff`） | `INNER` −2,−2 `#939393` + `INNER` 2,2 `#b6b6b6` |
| 状态点·绿（`#04ff00`） | `INNER` −2,−2 `#488747` + `INNER` 2,2 `#72c171` + `DROP` 2,2 |
| 状态点·黄（`#ffd000`） | `INNER` −2,−2 `#85752c` + `INNER` 2,2 `#d1b952` + `DROP` 2,2 |
| 状态点·红（`#ff0000`） | `INNER` −2,−2 `#853f3f` + `INNER` 2,2 `#da6868` + `DROP` 2,2 |
| 深色文字 | `DROP` x0 y1 `#6d6d6d` |
| 浅色文字 | `DROP` x0 y1 `#000000` @25% |
| 灰字 | `DROP` x0 y1 `#2a2a2a` |
| 凹槽细条 | `INNER` −1,0 `#000000` @25% |

内阴影色值不是算出来的，是逐个手调的（`#c8c8c8` 配 `#969696`/`#d6d6d6`，而 `#666666` 配 `#737373`/`#757575`，无统一规则），批量时必须逐节点原样复制，不能按公式推导。

效果写入：先建 EFFECT 样式再套，共 13 个 `SP/FX/*`（容器 · 凸起 · 凸起无投影 · 中灰 · 中灰带投影 · 凹下 · 白条 · 点绿 · 点黄 · 点红 · 凹槽 · 字深 · 字浅），13/13 实测套用成功；`node set --effects` 会返回成功但被事务后置校验回滚，正解是 `style apply <样式> <ids> --field effect`（单数）。

## 七、字体

全部文字用 Ark Pixel 12px Mono zh-Hans，字号只用 12 / 24 / 36 / 48，已建 4 个 Text Style（`SP/Text/12`、`SP/Text/24`、`SP/Text/36`、`SP/Text/48`）覆盖全部 184 个文字层。
文字层保持活的 TEXT，不转轮廓；改字体只能走 Text Style，`node set` 属性表里没有字体。
新生成器务必在每个 `<Text>` 上显式写 `font="Ark Pixel 12px Mono zh-Hans"`（不传会回落 Inter）。

## 九、已知缺口

1. 星球视窗 / 三维层相关控件：依赖 07-三维视窗.md 的三维实现，不是矩形能表达的。
2. 知识卡配图位（`Card/Knowledge` 的 `art` 区）：已有 78 张配图（见 10-知识卡配图.md），接入方式待定。
3. 骨架屏：需按真实内容结构排，现在排是猜。
4. 图表（趋势图、柱状图）：建议由图表库负责，不做成 Figma 组件。
5. `Bar/Progress` 默认变体现为 `stripe`（此链路无法改默认值），在 Figma 里把 `style=block` 拖到集合左上角即可。
