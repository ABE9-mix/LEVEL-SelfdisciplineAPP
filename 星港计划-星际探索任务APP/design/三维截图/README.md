## 一、本版关键变化（相比上一版）

| 项 | 上一版 | 本版 |
|---|---|---|
| 三维区域 | 358×180 卡片式（有圆角、有外边距） | **390×227 无界满幅**（无圆角、无外边距，直抵屏幕边缘） |
| 状态栏 / 标题 | 在画布**上方**的独立区块 | **浮在画布之上**（pointer-events: none） |
| 视角 | 星球居中全景（一颗球） | **地平线视角**（天空 1/3、星球 2/3，地平线横切画面） |

| 渲染倍率 | 跟随 DPR（上限 2） | **固定 2×** |

## 三、尺寸口径

| 项 | 值 |
|---|---|
| 设计基准 | 逻辑 **390 × 844** |
| 三维区域（逻辑） | **390 × 227** = 47 状态栏 + 180 内容区 |
| 三维画布（@2x） | **780 × 454** |
| 内容区左右安全边距 | 16（列表与工具栏 358 宽；三维部分**满幅无内缩**） |
| 三维 / 列表分界 | 逻辑 y = 227 |

**为什么三维是 390 宽而列表是 358 宽**：三维要"无界"，所以铺满到屏幕物理边缘；列表与分段选择器保留 16 边距。这个差异是设计意图，不是误差。

## 四、地平线视角参数（可复算）

| 项 | 值 | 说明 |
|---|---|---|
| 相机距球心 | **1.15 R**（离地 0.115R） | 贴近地表才有"地平线"而非"一颗球" |
| 光轴上抬 | **56.856°**（0.992332 rad） | 按「天空面积 = 1/3」反解 |
| 近裁剪面 | **0.001** | 相机到大气壳（1.035R）只剩 0.115R 余量 |
| 天空面积 | **33.3%**（几何）/ **30.5%**（实测，UI 浮层遮掉一部分） | — |
| 地平线高度 | 中央 **29.5%**、左右 **40.5%** | 曲率落差 11% |

**为什么是 1.15 而不是更远**：
- `d = 1.65` 时落差 47%，读起来是「一颗球」而不是「地平线」；
- `d = 1.06` 时落差仅 10%，但相机离大气壳只剩 0.025R，近裁剪面会切到。

## 五、像素规格（设计稿必须知道）

### 5.1 只在整数倍缩放下纯净

| 放置方式 | 结果 |
|---|---|
| **780×454**（原生 @2x） | ✅ 纯三维区板内率 **100%** |
| **1560×908**（2× 最近邻） | ✅ 同样纯净 |
| 390×227（1x） | ⚠️ Figma 双线性会糊掉块边 |
| 任意非整数尺寸 | ❌ 全失 |

**Figma 里正确做法**：用 780 或 1560 版，图片填充选 Fit，框尺寸保持整数倍。

### 5.2 已验证的三项数据

| 指标 | 数值 |
|---|---|
| 三维区色数 | **1,404**（关闭像素化时 2,895） |
| 纯三维区板内率 | **100.00%** |
| 全图板内率 | 94.57%（差额全是 UI 文字的抗锯齿，属预期） |
| 天空占比 | 30.5% |

> 注：文字浮层（状态栏、标题）是 CSS 渲染后叠在画布上的，会引入抗锯齿过渡色。
> 这是「无界三维 + 浮动 UI」这一设计本身的必然结果，不是像素化的缺陷。

## 八、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | 星球停在一个随机自转角度 | 每次导出角度不同；要固定需加"暂停自转"参数 |
| 2 | 设施是**盒体占位**（8 个），不是设计稿的 8 种形制族 | 因相机贴近地表，盒体只露出小方块，效果接近"地表建筑" |
| 3 | 分段选择器下方是**占位假数据** | 文案非最终内容 |
| 4 | 状态栏手绘（9:41 + 星港），无灵动岛 | — |
| 5 | 透明底版只有「计划」标签 | 需要另两个改编 `export-shots.mjs` 的 `data-k` |
| 6 | 三维区满幅后，列表内容被压短 | 逻辑上少 47pt；后续如需可视区域变大，可把三维缩到 200pt |
