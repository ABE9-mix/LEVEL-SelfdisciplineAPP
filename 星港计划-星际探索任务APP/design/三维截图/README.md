## 二、尺寸口径

| 项 | 值 |
|---|---|
| 设计基准 | 逻辑尺寸 **390 × 844**（iPhone 14/15/16） |
| 整屏 @2x | 780 × 1688 |
| 整屏 @3x | 1170 × 2532 |
| 三维视窗逻辑尺寸 | **358 × 180** |
| 三维视窗画布分辨率 | 716 × 360（DPR 2） |
| 内容区左右安全边距 | 16（内容宽 358） |

**为什么视窗是 716×360 而不是 358×180**：视窗在 DPR 2 的设备上以 2 倍像素渲染，
所以物理像素是 716×360。设计稿若按 1x 逻辑尺寸排，用 358×180 放置即可
（或直接用 2x 图缩放一半，比例完全一致）。

## 三、像素规格局限（设计时必须知道）

### 3.1 像素化只在整倍数下保持纯净

| 放置方式 | 结果 |
|---|---|
| 按 **716×360** 原尺寸放 | ✅ 100% 纯像素，块边精确 4px |
| 按 **1432×720 / 2148×1080**（整数倍）放 | ✅ 同样纯净（最近邻放大版已备好） |
| 按 **358×180**（1x 逻辑）放 | ⚠️ 会触发缩放，Figma 若用双线性会把块边糊掉 |
| 按 **任意非整数尺寸**放 | ❌ 块边会被重采样，纯度全失 |

**在 Figma 里正确做法**：
1. 用 `04-...-716x360.png` 或 `1432x720` 版；
2. 双击图层 → 图片填充 → 勾选 **Fit**，并确保框尺寸是 716 或 1432 的整数倍；
3. 若必须缩放到 358 宽，请**先把 Figma 画布换成 2x 基准**（780×1688 的屏），再按 716 放。

### 3.2 已经替你规避的三个坑

导出时页面已自动处理（不需要你手动改）：

| 项 | 处理 |
|---|---|
| 圆角 | 像素化开启时 `border-radius` 归零（圆角会让四角抗锯齿混出板外色） |
| 描边 | 用 `outline` 而非 `border`（border 会占内容区导致非整数缩放） |
| 柔光叠层 | 像素化开启时关闭（否则整屏变板外色） |

所以图里的视窗是**方角 + 1px 描边**，与项目 `radius/none = 0` 规范一致。

## 四、色板（可直接吸色）

三维视窗内使用 **16 色**，全部来自项目规范（07 §4.2 相位色板 + §4.3 accent）：

```
#03050A  #0A1020  #101A2C  #151C2E
#1D3352  #24344E  #2A3550  #3A2F44
#3A5A80  #4A6FA5  #5A9BD4  #5FBF8F
#7FA3C9  #C98A5A  #E8A468  #F2E4C9
```

**实测**：`04-三维视窗-像素化开-716x360.png` 全图仅 **14 种颜色**，
且 **100% 落在这 16 色内**，没有任何插值过渡色——可以直接吸色进设计稿。

> 对比：`05-...像素化关...png` 有 **7,578 种颜色**。两张放一起就是很好的"为什么做像素化"的对比图。

## 六、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | 整屏图是**静态截图**，星球停在一个随机自转角度 | 每次导出角度不同；若要固定角度，需在页面里加"暂停自转"再导出 |
| 2 | 设施（橙色/绿色小方块）是**立方体占位**，不是设计稿的 8 种形制族 | 正式稿需换成真实形制模型 |
| 3 | 分段选择器下方列表是**占位假数据** | 文案非最终内容 |
| 4 | 顶部状态栏是**手绘的**（9:41 + 星港） | 不含灵动岛 |
| 5 | 透明底版只有「计划」标签 | 如需另两个标签的透明底，改 `export-shots.mjs` 里 `data-k` 再跑 |

## 七、重跑方式

```bash
node demo/export-shots.mjs
```

会清空并重写本目录（`design/三维截图/`）。
若改了页面（配色、布局、尺寸），重跑即可同步。
脚本用 Chrome headless + CDP，**重启时务必先关掉已有 chrome 进程**，
否则可能连到错误的调试目标（脚本已内置重试，但干净启动更稳）。
