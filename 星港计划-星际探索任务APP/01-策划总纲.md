# 01 · 策划总纲

---

## 一、产品定位

**星港 STARPORT** 是一款以**星际探索**为世界观的任务计划应用。用户扮演一座航天中心的指挥官：

- 把现实里想坚持的领域，**成立为一个机构**（体能署、膳食司、静观室…）；
- 给机构**设立计划**（8 周力量、30 天晨跑、一门烹饪课）；
- 用**航天任务**的形式去执行它——番茄钟专注对应"点火入轨"，早起闹钟对应"发射窗口过境"；
- 每次成功换回两样东西：**推进值**（让星港变高）与**研究成果**（一段真实的天文知识）；
- 星港随累计推进**逐格扩建**，指挥官可以命名设施、换涂装、定制徽记；
- 结算时有一层**随机扰动**：概率触发彩蛋，让"完成一次"这件事始终带着一点期待。

**定位一句话**：把自律计划装进一座会成长的星港，让它顺手教人一点真实的宇宙。

| 层 | 主张 | 面向的用户问题 |
|---|---|---|
| 工具层 | 计划、任务、番茄钟、闹钟四件事在一条流程里闭环 | "记录和执行要来回切两个 App" |
| 表达层 | 进度不是一根灰条，是一座会亮起来的星港 | "看不到进步，坚持不下去" |
| 内容层 | 完成换来真实天文知识，不是虚拟金币 | "打卡打得很空，不知道得到了什么" |
| 情绪层 | 概率彩蛋 + 集卡 + 命名权 | "每天一模一样，无聊" |

## 二、核心价值主张

1. **组织感**：机构（领域）→ 计划（周期目标）→ 任务（动作）三层结构，比一张平铺的 to-do 列表更接近人管理自己的方式。用户不是在"完成任务"，是在"经营一个部门"。
2. **可感知的积累**：星港的高度、亮着的窗、扩建的舱段，是"我花时间去了哪里"的空间化答案。数字会麻木，建筑不会。
3. **寓教于乐的正当性**：知识卡是**完成现实动作之后**才解锁的，因此它是奖励而不是负担；用户不会觉得"我在被教育"，而是"我赢了个东西，顺便知道地球一天其实是 23 小时 56 分"。
4. **期待感**：结算前的 0.6 秒扰动，是整款产品唯一被设计出来的"心跳"。它便宜、可截图、可复述（"我今天抽到彗星了"）。

## 三、目标用户

### 核心人群

| 人群 | 特征 | 星港给什么 | 主要落点 |
|---|---|---|---|
| **计划囤积型** | 收藏了大量健身课表、书单、食谱，从没执行完过一个 | 机构 = 一次只立一个承诺；计划模板一键成立 | 机构 / 计划创建 |
| **计时孤独型** | 用过番茄钟，但"25 分钟结束什么也没发生" | 入轨动画 + XP + 知识卡 + 概率彩蛋 | 执行层 / 结算 |
| **早起失败型** | 闹钟响了继续睡，缺一个"必须赴约"的理由 | 发射窗口：一个有时刻、有名字、会错过的东西 | 发射窗口 |
| **收集与养成型** | 需要"我的东西在变多"才会持续投入 | 星图只增不减、知识卡集册、星港扩建、命名权 | 星图 / 养成 |
| **宇宙好奇型** | 本身喜欢天文，需要一个坚持学一点什么的载体 | 知识卡体系 + 星学苑机构 + 观测任务 | 内容层 |

### 次要人群

学生（自习/复习专注）、备考者、居家办公者（切分深度工作）、习惯重建期用户（戒熬夜、恢复运动）。

### 明确不服务

需要团队协作、甘特图、跨端日历同步的项目管理用户；需要重度数值养成的游戏用户；追求社交比拼的用户。

## 四、竞品与差异

| 品类 | 代表形态 | 它们的强项 | 它们的空位 → 星港的打法 |
|---|---|---|---|
| 专注计时器 | Forest（种树）、番茄 ToDo、Flora | 计时稳定、单一动作反馈明确 | 只有"一次"，没有"组织"。星港有机构→计划→任务三层，且树/港是长期资产 |
| 习惯打卡 | Habitica（RPG）、 Finch（宠物）、Streaks | 角色/宠物陪伴、连续天数 | Habitica 的战斗数值与真实行动脱钩（可以刷）；Finch 只给情绪不给信息。星港给**知识**且知识不可刷 |
| 游戏化自律 | 各类 RPG 化 to-do | 等级、装备 | 普遍重度数值 + 商城，把自律变成打工。星港**无商城、无消耗、无体力** |
| 教育科普 App | 星空、Stellarium、NASA App | 天文内容权威 | 只有内容没有行为改变。星港把内容变成**奖励**，因此有内在动机 |
| 闹钟类 | Sleep as Android、正日 | 精确唤醒、睡眠统计 | 唤起后没有承接。星港的窗口过境直接连到当日第一条任务 |

**差异主张（对外一句话）**：

> 别的 App 让你打卡，星港让你**用打卡换来的时间，建一座自己的星港，并知道一点真实的宇宙**。

三个护城河：

1. **机构化组织**（别人是列表，我们是编制）；
2. **知识作为奖励**（别人是虚拟币，我们是可核查的真实天文）；
3. **概率公开的中性彩蛋**（别人用 FOMO 促活，我们只加期待不减安全）。

## 五、北极星与辅助指标

**北极星：周有效入轨分钟数 / 活跃指挥官**（Weekly Effective Orbit Minutes，WEOM）
——只统计被判定成功的执行时长，不统计打开次数、不统计打卡点击数。选它的理由：同时代表"真的自律了"（用户价值）和"还在用"（业务价值），且无法靠刷 UI 提高。

| 指标族 | 指标 | 目标（上线 3 个月参考值） | 说明 |
|---|---|---|---|
| 激活 | 首周 D1 留存 | ≥ 45% | 首日完成 ≥1 次点火是激活定义 |
| 结构 | 建立第 2 个机构的用户占比 | ≥ 30% | 机构是复用价值的入口 |
| 执行 | 点火完成率（启动→成功） | ≥ 80% | 低于此值说明中断惩罚过重 |
| 执行 | 窗口过境 30 分钟内记录率 | ≥ 55% | 早起真实性的关键 |
| 内容 | 知识卡完整阅读率 | ≥ 60% | 寓教于乐是否成立的直接判据 |
| 内容 | 卡内延伸词二次点击率 | ≥ 20% | 求知欲是否被激发 |
| 情绪 | 单次结算页停留 | 2–6 s | 过短=无感，过长=设计噪音 |
| 情绪 | 稀有扰动触发的分享/截图 | 观测项 | 不设 KPI，避免为分享扭曲设计 |
| 长期 | 8 周计划完成率 | ≥ 35% | 与工具类基线（约 20%）对比 |
| 长期 | 第 8 周仍活跃率 | ≥ 25% | 养成层是否起作用 |

**明确不设的指标**：DAU 拉新裂变、在线时长、签到连续天数强绑定推送。任何把"多待在里面"当作目标的指标都与自律产品的初衷相反。

## 六、MVP 范围（v1.0）

| 模块 | 进 MVP | 说明 |
|---|---|---|
| 机构 | ✅ | 8 个预置模板 + 全自定义（名称/代号/徽记/域色） |
| 计划 / 任务 | ✅ | 周期 + 频率 + 休息日 + 提醒；任务拆分 |
| 点火（番茄钟） | ✅ | 15/25/45/60 档 + 自定义；本地精确计时 |
| 发射窗口（闹钟） | ✅ | 系统级精确闹钟 + 醒后记录任务；周末/工作日分组 |
| 推进值 / 指挥官等级 | ✅ | Lv.1–30 |
| 研究成果 · 知识卡 | ✅ | **首批 60 张**，6 系列 × 10；三级稀有度 |
| 星图 | ✅ | 只增不减；4 级缩放；搜索已收录对象 |
| 星港扩建 | ✅ | **4 设施 × 3 级**（枢纽/生保/动力/观测台） |
| 个性化 | ✅ | 中心命名、徽记编辑、4 套涂装、日志背景（4 张真实天文图） |
| 轨道扰动（彩蛋） | ✅ | 4 层概率 + 10 个具体彩蛋 + 日历限定 |
| 复盘 | ✅ | 周报：趋势线 + 机构对照 + 本周成果集 |
| 备份导出 | ✅ | JSON / CSV 本地导出（不做云账号） |
| ❌ 不做 | 商城、消耗型货币、体力、排行榜、社交、组队、UGC 内容、AI 生成计划、付费抽卡、云同步账号体系、多端协同 |

**理由**：MVP 必须先证明"三层组织 + 执行 + 知识奖励 + 轻量养成"能让人坚持，而不是一次做完 8 设施 40 级。养成与彩蛋只做"能验证期待感"的最小量。

## 七、版本路线

| 阶段 | 时间 | 交付 | 要回答的问题 |
|---|---|---|---|
| **P0 骨架** | 2 周 | 机构/计划/任务 CRUD + 点火 + XP/等级 | 三层组织比平铺列表真的更好用吗（可用性测试 5 人） |
| **P1 闭环** | 4 周 | 发射窗口 + 结算 + 60 张知识卡 + 星图 | 知识作为奖励是否被读完、是否想读下一张 |
| **P2 期待** | 6 周 | 轨道扰动（4 层 + 10 彩蛋）+ 保底 | 随机量提升打开欲，还是变成噪音 |
| **P3 归属** | 8 周 | 4 设施 × 3 级 + 命名/徽记/涂装 | 养成是否延长 8 周留存，而不只是好看 |
| **P4 沉淀** | 12 周 | 周报/月报、前后对照、导出备份 | 用户能否回答"三个月前我是什么样" |
| **P5 扩展** | 16 周后 | 补齐 8 设施 + 12 机构模板 + 200 张卡 + 观测日历 | 内容量是否构成留存壁垒 |

## 八、商业化（后置，不进 MVP）

| 方案 | 内容 | 红线 |
|---|---|---|
| 一次性解锁 Pro | 高级涂装 / 深度统计 / 无限机构 / 知识卡全册 | **不得卖概率、不得卖稀有卡、不得卖推进值** |
| 知识内容包 | 与天文机构/科普方授权的专题册（如"深空天体 200 卡"） | 免费层必须留够完整闭环 |
| 周边 | 星图打印、徽记贴纸（把用户自己命名的星港做成实物） | 非必需，不做实物墙 |

绝对不做：订阅制阻断核心自律功能、抽卡式付费、广告插进计时过程、任何形式的连续天数罚款。

## 九、风险与对策

| # | 风险 | 信号 | 对策 |
|---|---|---|---|
| 1 | **三层组织变重**：机构/计划/任务变成"管理工具的管理工具" | 建机构后 7 天内未创建任务；设置页耗时 > 执行耗时 | 强制模板优先（一键成立，3 步 ≤60 秒）；机构字段默认折叠；新手只推 1 个机构 |
| 2 | **知识卡疲劳**：重复、错漏、被当作说教 | 完整阅读率下滑；卡片跳过率高 | 每卡 ≤120 字；错误率红线 <0.5%（双人核查 + 来源字段）；同一卡永不重复发；允许关闭扰动 |
| 3 | **随机变赌博**：用户为抽卡而刷任务 | 单日启动次数与扰动结果强相关 | XP 递减曲线（同日第 4 次起大幅衰减）；扰动只在"首次入轨/首次计划节点"触发；稀有每日上限 1 次 |
| 4 | **早起闹钟不可信**：用户 snooze 后伪造记录 | 窗口过境与设备使用数据矛盾 | 醒后 30 分钟记录窗；需一次真实交互（滑动/算术）；过期只标"未确认"，**不倒扣历史** |
| 5 | **养成失衡**：数值党把星港当游戏，自律被架空 | 用户为升设施选择低价值任务 | 无消耗系统（不能"刷 XP 换建筑"）；设施升级只看**累计航时 + 领域广度**，不看 XP 总量 |
| 6 | **主题稀释**：太空皮 vs 真实内容互相打脸 | 用户吐槽"月亮离我 40 万公里"式滥用 | 所有数值与单位一律使用真实天文数据（见 02 附录），宁可少一句文案，不可错一个数字 |
| 7 | **Android 厂商杀后台**：闹钟不准时 | 唤醒失败率投诉 | 前台服务 + 精确闹钟权限引导 + 双链路（系统日历镜像 + 云端推送兜底）+ 掉线自查页 |
| 8 | **内容准确性责任**：科普出错 | 单条纠错 | 每张卡带来源字段与更新日期；内置纠错入口；版本号写入导出 JSON |

## 十、待验证问题（留给用户测试）

| # | 假设 | 怎么验 | 失败了就改什么 |
|---|---|---|---|
| 1 | "机构"这一层是加分还是负担 | A/B：平铺任务列表 vs 三层结构，测 8 周完成率与创建耗时 | 机构降级为可选的"分组标签" |
| 2 | 知识卡作为奖励是否比虚拟币更有效 | 三组：知识卡 / XP-only / 知识卡+XP，测留存与主动阅读 | 知识改为"自选奖励"入口 |
| 3 | 概率彩蛋能否提升打开欲而不制造赌博感 | 埋点：扰动关闭率、结算页停留、单日启动分布 | 概率降到只有 T3 一层，或提供"纯专注模式" |
| 4 | 发射窗口（闹钟）的真实完成率 | 记录窗实测：30 分钟内确认率 | 改为"醒后补记"弱承诺 + 周报诚实呈现 |
| 5 | 4 设施 × 3 级是否已足够"有奔头" | 访谈 + 升级前后 7 日活跃差 | 加"外观里程碑"而非加数值层级 |
| 6 | 命名/涂装是否产生归属感 | 自定义使用率；导出/分享率 | 保留命名权作为唯一深度自定义 |
| 7 | 番茄时长档位（15/25/45/60）是否匹配真实自习节律 | 档位使用分布与完成率 | 改成"自选分钟 + 推荐档" |
| 8 | 太空主题对非天文兴趣用户的接受度 | 用户访谈中"我不关心星星"的出现频率 | 主题提供"无科普纯结构"模式 |

## 十一、内容生产规范（60 张卡的成本模型）

| 项 | 规格 |
|---|---|
| 单卡工作量 | 查证来源 15–25 min + 撰写 10 min + 交叉核对 5 min ≈ **40 min/张** |
| 60 张 | ≈ 40 人时（1 人一周，或 2 人两天） |
| 200 张（P5） | ≈ 133 人时 + 编辑审核 20% |
| 质量红线 | 双人独立核对；每个数字有来源；单位统一 SI；避免过时结论（附检索日期） |
| 风险条款 | 涉及前沿争议（如哈勃常数、银河系直径）必须写区间与"仍在修订" |

## 十二、成功定义（一年后怎么看这件事）

| 层级 | 达成线 |
|---|---|
| 行为 | 至少 40% 活跃用户在第 8 周仍在执行同一份计划 |
| 内容 | 知识卡平均完整阅读率 ≥ 60%，且出现"我去看了真天文台网站"的自述 |
| 表达 | 星港被自定义（改名或换涂装）的比例 ≥ 50% |
| 口碑 | 用户能用自己的话讲清"我为什么没放弃" |

一句话验收：**用户留在星港，是因为它让他的时间有了形状，而不是因为它扣了他的东西。**
