# 08 · 技术方案

> 课程设计尺度：本地优先（无账号也能完整使用）、无云依赖（v1 不做账号体系）、可导出（数据属于用户）。三维选型与性能目标见 07-三维视窗.md。

## 一、技术选型
| 层 | 选择 | 理由 |
|---|---|---|
| 三维渲染 | WebView + three.js（WebGL2 基线，WebGPU 可选加速、不进验收门） | 只有顶部 358×180 视窗，详见 07-三维视窗.md |
| 平台 | iOS + Android，原生外壳 + 单个 WebView 三维视口 | 闹钟/通知/存储仍走原生 |
| 本地存储 | SQLite（结构化）+ 文件（贴图/模型） | 查询与迁移都稳 |
| 状态管理 | 单向数据流 + 事件溯源（执行记录是不可变事件） | 回滚与统计都靠事件 |
| 通知/闹钟 | 平台原生（UNCalendarNotificationTrigger / AlarmManager） | 精确闹钟必须原生 |
| 同步 | v1 不做；导出 JSON / CSV | 无账号、无云 |

## 三、不可变性规则
| 规则 | 做法 |
|---|---|
| 执行记录只增不删 | 删除机构 = state 改 archived，session 全保留 |
| 重置计划不改历史 | 新建 program 行（cycle_index+1），旧行 state=reset |
| XP 不回退 | commander.xp_total 只增，DB 层触发器对更小值 RAISE(ABORT) |
| 星图只增 | starmap_node 不给 DELETE 权限 |

## 四、关键算法

**4.1 光照相位**（输入 → 7 步 → 相位判定；与天文年历误差 ≤15 分钟）
输入：unix 时间 t、纬度 lat、经度 lon、时区偏移 tz；全本地计算，当日日出日落缓存一次。
1. 儒略日 JD = t/86400 + 2440587.5。
2. 太阳平黄经 L、平近点角 g（低精度太阳位置，误差 <0.01°）。
3. 赤纬 δ = asin(sin ε · sin L)，ε = 23.4397°；时差 EqT 由 L、g 求得，约 ±16 min。
4. 真太阳时 TST = UTC小时 + lon/15 + EqT/60；时角 H = 15° × (TST − 12)。
5. 高度角 alt = asin(sin lat·sin δ + cos lat·cos δ·cos H)。
6. 相位判定：alt > 0° → day；−6°~0° → dawn（上午）/ dusk（下午，按 H 符号）；−12°~−6° → dusk 深段 / night 起始；−18°~−12° → night；alt < −18° → deep。
7. 极昼极夜：|lat| 偏高且当日 δ 与该半球同号 → polar。

**4.2 计时防漂移**
```
start = monotonicClock(); elapsed = monotonicClock() - start   # 前台 tick 只重绘，不累加
```
| 场景 | 处理 |
|---|---|
| 切后台 | 保存 start + wall_clock_at_start |
| 回前台 | 用墙钟差重算，与单调时钟差 >2s 时以墙钟为准（防休眠停表） |
| 进程被杀 | 从 DB 读回未完成 session，标记 interrupted，用户选「计入中止 / 丢弃」 |
| 系统时间被改 | 墙钟倒退 >60s 只用单调时钟，并标 clock_anomaly |

**4.3 XP / 递减 / 结算**
```
settle(session):
  decay  = DECAY[min(day_seq, len(DECAY)) - 1]
  tierK  = {light:0.8, standard:1.0, deep:1.3}[program.tier]
  xp     = round(XP_IGNITE(target_min, ratio) * decay * tierK)
  rc     = max(1, round(RC_BASE * decay))
  if disturbance_enabled:
    tier = roll_disturbance(pity, day_limit, month_cap)
    xp   = apply_bonus(xp, tier)          # 当日生效，取当日最高，不叠加
    if tier in [T3,T4]: grant_card(rare)  # 每日 ≤1
  grant_card(per_rules)                   # 普通概率
  commit_immutable(session, xp, rc)
```

## 五、闹钟与通知
| 平台 | 机制 | 注意 |
|---|---|---|
| iOS | UNCalendarNotificationTrigger（重复）+ 关键闹钟（iOS 26+ AlarmKit 可用则优先） | 必须取得通知与声音授权，无静默降级 |
| Android | AlarmManager.setExactAndAllowWhileIdle + SCHEDULE_EXACT_ALARM | 引导电池白名单；国产 ROM 差异大 |
| 双链路兜底 | ① 本地精确闹钟 ② 系统日历镜像事件（带提醒） | 第二链路无需网络；v1 不做云端兜底 |
| 自检页 | 显示最近 3 次「设定时间 vs 实际触发时间」偏差；连续 2 次 >2 分钟提示加白名单 | 把不可靠变得可见 |

通知文案不写「该起床啦」，写「07:00 窗。」，文案规则见 02-世界观与文案.md。

## 六、埋点原则
- 只记事件名与计数，不含任何内容文本；15 个核心事件覆盖打开、点火、结算、阅读、扰动、窗口。
- 诚实指标：窗口确认率、知识卡完整阅读率、地图参与度（<20% 说明地图是装饰）；北极星 WEOM = Σ 成功执行时长 / 周活跃指挥官数。

## 七、隐私与数据
| 项 | 做法 |
|---|---|
| 定位 | 可选，拒绝则用手动城市（误差 <30 分钟） |
| 上传 | v1 不上传任何数据，无账号、无云 |
| 导出/删除 | JSON 全量 + CSV 记录一键导出；清空先给用户一份 |
| 分析 | 遥测可完全关闭；开启时只有事件名与计数，无内容 |

## 八、里程碑与风险
里程碑与验收沿用 01-产品与定位.md 的版本路线，不在此单列。
- 三维：WebView 首帧、内存、上下文丢失是真实风险，靠预热 + 占位图 + 自动降档兜底。
- 闹钟：Android 不准，靠双链路 + 自检页 + 诚实呈现（不倒扣）。
- 相位与计时：单测覆盖 10 组已知日出日落，误差 >15 min 即回归失败；计时用墙钟校正 + 异常标记。
