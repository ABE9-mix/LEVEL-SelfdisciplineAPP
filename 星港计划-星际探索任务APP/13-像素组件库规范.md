## 一、这套东西解决了什么

你手摆的板里有三个问题，不是"不好看"，而是**同一件东西有多个版本**：

| 问题 | 实测 | 后果 |
|---|---|---|
| 同一元素多个尺寸 | 「任务状态按钮」出现 **113 / 117 / 121 / 124** 四种宽度；按钮高度有 30 / 40 / 45 三种 | 拼界面时每处都要手动对齐 |
| 同一语义多个色值 | 红有 `#ff0d00` + `#ff0000`；黄有 `#ffe100` + `#ffd000`；**灰阶多达 17 个** | 改一次主色要翻遍全稿 |
| 重复绘制 | 任务卡画了两遍（`823:94` / `874:374`）；分段器也画了两套（散装 + 成组） | 改一处忘一处 |

标准化后：**33 个令牌 + 7 个组件集 / 26 个变体**，全部由变量驱动。

| `Card/Knowledge` | ✅ `Body`、`Code` | 两变体共用同一张卡 |
| `Bar/Nav` | ✅ `Title` | 每屏标题不同 |
| `Field/Input` | ✅ `Text` | 输入内容 |
| `Block/Ring` | ✅ `Time` | 剩余时间 |
| `Card/Event` | ✅ `Title`、`Body` | 事件文案 |
| `Card/Program` | ✅ `Title` | 计划名 |
| `Card/Facility` | ✅ `Name` | 机构名 |
| `Panel/Dialog` | ✅ `Title`、`Body` | 弹层文案 |
| `Toast` | ✅ `Text` | 提示文案 |
| `Card/Task` | ✅ `Time` | 时间（示例 15:00） |

**这条是实测出来的，不是设计偏好**：跨变体共享的文字属性**只有一个值**。
我一开始给 Chip 和 Btn/Status 也加了文字属性，结果四个 chip 全变成「待确认」、两个状态按钮全变成「终止」——
因为给其中任一变体赋值，会同步到全部变体。所以**"文案由变体决定"的地方就不能用文字属性**，已撤掉这些属性并逐变体还原了文案。

## 五、怎么用

```
1. 从 Assets 面板拖组件 → 改变体属性（右栏）→ 改文字属性（若有）
2. 改颜色：动 SP/Color 里的变量，所有实例跟着变（不要手动改实例填充）
3. 新组件：先复用上面 **25 个**；确实需要新的，再按同一套令牌做
4. 拼页面：内容宽用 358，左右安全边距 16（与线框稿一致）
5. **约束视觉**：只动 `SP/Color` / `SP/Metric` 的变量值，不要改组件里的字面值——
   两批共 664 处引用都绑在变量上，改变量即全局生效
```

**不要做的事**：

- 不要再从手摆板复制矩形去拼界面（会带回 361/30/45 这些离群值）；
- 不要在实例里手动改颜色（改用变量，否则改主色时会漏掉这些实例）；
- 不要给"文案由变体决定"的组件加文字属性（见 3.1 的原因）。

## 七、重要修正：字体走错了，且不该重画

### 7.1 字体（已修）

第一、二批组件的文字**全是 Inter，不是 Ark Pixel**。

根因：JSX 渲染器源码 `jsx-render.js:882` 写的是 `const family = item.font || 'Inter'`——
`<Text>` 支持 `font` 属性，**不传就回落 Inter**，而我的生成器没传。

修法：`node set` 的能力表（`NODE_SET_PROPERTIES`）**不含任何字体属性**，改不了字体；
但 **Text Style 可以**。已建 4 个样式并套到全部 **184 个文字层**：

| 样式 | 字号 | 字体 |
|---|---|---|
| `SP/Text/12` | 12 | Ark Pixel 12px Mono zh-Hans |
| `SP/Text/24` | 24 | 同上 |
| `SP/Text/36` | 36 | 同上 |
| `SP/Text/48` | 48 | 同上 |

新一轮生成器务必在每个 `<Text>` 上显式写 `font="Ark Pixel 12px Mono zh-Hans"`。

### 7.2 不该重画（方向修正）

原做法是"用令牌把视觉重画一遍"——**这是错的**。手摆板里的图形已经逐像素对齐、
视觉就是目标效果；重画等于用我猜的数字替换你已经调好的像素。

**修正后的原则**：

| 类别 | 处理 |
|---|---|
| 文字 | 保持活的可改（Ark Pixel + 文字属性） |
| 按钮 | 填充保持可变（绑颜色变量） |
| 状态指示器 | 颜色保持可变 |
| **其余全部** | **原样保留，不做参数化**（等价于固定 SVG，够用） |

### 7.4 命名约定（避免重名）

我重画的那两批属于**结构模板**，与正式件重名会让 Assets 面板出现同名项。
故重画件统一加前缀 **`模板/`**（25 个），手摆来源的正式件不加前缀（3 个）。
当前 **28 个组件集，重名 0**。

> 已验证：`node reparent` 报 `dispatch:failed` 时**不一定是失败**——
> 原 GROUP 被移入后子节点逐个迁出，组降到 1 个成员会自动解散，
> 最后一个元素会报 already-moved，但**终态正确**。判断成败要看终态树，不要只看返回值。

## 八、矩形体积感（用户声明的原则 + 效果配方）

### 8.1 用户声明的六条原则

| # | 原则 | 落地 |
|---|---|---|
| 1 | 尽量保持视觉对齐 | 组件从手摆节点直接归组，`node reparent` 保留画布坐标 |
| 2 | **数字占位长度固定** | 计时/编号/数值类文字框宽度不随内容变化，避免跳动 |
| 3 | **内部元素与外框边距统一** | 同一组件内边距取齐（待批量时逐组件校验） |
| 4 | **单个组件内增加层次** | 计划卡 / 设施卡的强调文字用 **24**（正文 12） |
| 5 | 分段选择器配色按手摆板的来 | 选中 `#c8c8c8` 浅底黑字 / 未选中 `#151515` 深底灰字 |
| 6 | 每个元素外框矩形要有**无模糊投影 + 内阴影**塑造体积感 | 见 8.2 |

### 8.2 效果配方（全部提取自手摆板，**blur 一律为 0**）

手摆板的矩形**本来就带这些效果**；我上一轮重画时丢了，所以看起来"平"。

### 8.3 ⚠️ 两个已证实的坑（务必遵守）

#### 坑 1：`node set --effects` 不可用（会被事务回滚）→ **正解是 EFFECT 样式**

我第一版试片用 `node set <id> --effects <JSON>` 写效果，命令**返回成功**，
但复查发现 **effects 是空的**。加重试后拿到真实报错：

```
Node Set failed with rolled-back: fresh postcondition did not match every requested property
[mutation:rolled-back attempted:1 restored:1 residue:0]
```

**原因**：该链路有事务后置校验，Figma 读回的 effect 与我写入的不完全一致
（归一化差异），verifier 判定失败 → **整体回滚**。所以"返回成功"是假象。
（与 §原型 的 bug 同类。）

**✅ 正解：先建 EFFECT 样式，再 `style apply … --field effect`**

```powershell
# 1) 建样式（一次，可复用）
figma_run ["style","create","EFFECT","SP/FX/凸起","-p",
  '{"effects":[{"type":"INNER_SHADOW","color":{"r":0.588,"g":0.588,"b":0.588,"a":1},
   "offset":{"x":-2,"y":-2},"radius":0,"spread":0,"visible":true,"blendMode":"NORMAL"}, …]}']

# 2) 套到任意节点（注意是 effect 单数，不是 effects）
figma_run ["style","apply","SP/FX/凸起","123:456,123:457","--field","effect"]
```

**关键点**：`--field` 必须是 **`effect`（单数）**；
写 `effects`（复数）会报 `command-rejected`，且**静默不生效**。

已建 13 个样式（`SP/FX/*`），**13/13 实测套用成功**：
容器 · 凸起 · 凸起无投影 · 中灰 · 中灰带投影 · 凹下 · 白条 ·
点绿 · 点黄 · 点红 · 凹槽 · 字深 · 字浅

> 比"复制节点"更好的地方：**能套到任意节点**，包括你自己画的矩形，
> 不需要去找一个同色同尺寸的源节点。

#### 坑 2：`node duplicate` 的返回里有两个 id，必须取第二个

```
Duplicated "组件板-手摆" (807:180) as "组件板-手摆" (890:1281) in ... 
                          ↑源 id                    ↑新 id
```

我第一版用「取第一个 id」的通用解析，结果 **把源节点当成复制件**去改名、搬走，
随后又删掉了那个画板 —— **导致原节点被删除**。

影响与恢复：
- 原始 `组件板-手摆`（`807:180`）**未受影响，84 个子节点完好**（我只在副本上操作）
- 受损的是我复制出的副本，以及**用户放在试片里的「样例」组**（随试片画板一起被我删掉）
- 已恢复：重新复制得到干净副本 **`903:1643`（84 子节点，与原始一致）**；
  「样例」组按原结构重建为 **`样例（已恢复）`**

**正确解析**：`const newId = raw.match(/ as .*?\((\d+:\d+)\)/)[1]`

#### 坑 3：`figma_render` 的根元素必须是 `<Frame>`

裸 `<Text>` 作根会被拒：`Invalid JSX: root element must be <Frame>`。
我批量加分区标签时全部静默失败（只检查返回里有没有 id，没看错误），
导致标签一个都没进去。

**正解**：把所有标签包进一个临时 Frame 渲染，再 `node reparent` 取出 Text，最后删掉包装帧。
