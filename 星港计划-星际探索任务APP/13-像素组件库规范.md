# 13 · 像素组件库规范（Figma）

> 来源：从 `组件板-手摆`（`807:180`）归纳标准化，**素材原板未做任何改动**。
> 产物：Figma 页 `STAR` → 画板 **`组件库-标准 v1`（节点 `881:430`）**，位于 x≥2600 空区。
> 页面截图：[design/组件库-标准.png](design/组件库-标准.png)

## 一、这套东西解决了什么

你手摆的板里有三个问题，不是"不好看"，而是**同一件东西有多个版本**：

| 问题 | 实测 | 后果 |
|---|---|---|
| 同一元素多个尺寸 | 「任务状态按钮」出现 **113 / 117 / 121 / 124** 四种宽度；按钮高度有 30 / 40 / 45 三种 | 拼界面时每处都要手动对齐 |
| 同一语义多个色值 | 红有 `#ff0d00` + `#ff0000`；黄有 `#ffe100` + `#ffd000`；**灰阶多达 17 个** | 改一次主色要翻遍全稿 |
| 重复绘制 | 任务卡画了两遍（`823:94` / `874:374`）；分段器也画了两套（散装 + 成组） | 改一处忘一处 |

标准化后：**33 个令牌 + 7 个组件集 / 26 个变体**，全部由变量驱动。

## 二、令牌（Tokens）

建了两套变量集合（此前文件里**没有任何变量集合**，不影响别处的 CP 系统）：

### 2.1 `SP/Color` — 17 个

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg/void` | `#000000` | 最底层、画板底 |
| `bg/sunken` | `#151515` | 未选中态、凹槽 |
| `bg/base` | `#2c2c2c` | 卡片、容器底 |
| `bg/raise` | `#4b4b4b` | 次级表面、占位图 |
| `line/strong` | `#c8c8c8` | 主描边（2px） |
| `line/soft` | `#a9a9a9` | 细描边（1px） |
| `line/track` | `#666666` | 进度轨道、禁用底 |
| `text/primary` | `#ffffff` | 一级文字 |
| `text/inverse` | `#000000` | 浅底上的字 |
| `text/secondary` | `#b0b0b0` | 二级文字 |
| `text/disabled` | `#7e7e7e` | 禁用、未选中 |
| `text/muted` | `#666666` | 极弱信息 |
| `accent/go` | `#04ff00` | 成功点、状态灯 |
| `accent/go-deep` | `#2bbf18` | 绿色按钮底（黑字可读） |
| `accent/stop` | `#ff0d00` | 终止、危险 |
| `accent/warn` | `#ffe100` | 编号、警示 |
| `accent/confirm` | `#4d8fd6` | 确认（蓝） |

**收敛情况**：灰阶 **17 → 10**；红 **2 → 1**；黄 **2 → 1**；
绿保留两个——它们分工不同（`go` 是发光点，`go-deep` 是按钮底，黑字压在亮绿上读不清），不是重复。

### 2.2 `SP/Metric` — 16 个

| 令牌 | 值 | | 令牌 | 值 |
|---|---|---|---|---|
| `space/1..5` | 4 / 8 / 12 / 16 / 24 | | `h/sm` | 32 |
| `stroke/thin` | 1 | | `h/md` | 40 |
| `stroke/thick` | 2 | | `h/lg` | 48 |
| `radius/none` | 0 | | `content/w` | 358 |
| `type/micro` | 12 | | `type/num` | 24 |
| `type/title` | 36 | | `type/hero` | 48 |

**保留你的两个正确决定**：

- **零圆角**（全稿 100% 直角）——这是像素风的骨架，已固化为 `radius/none = 0`；
- **字号只用 12 / 24 / 36 / 48**——正好是 Ark Pixel 12px 的整数倍，没有重采样，像素纯度没被破坏。

## 三、组件库（7 个组件集 / 26 个变体）

| 组件集 | 变体轴 | 尺寸 | 说明 |
|---|---|---|---|
| `Seg/Bar` | `sel` = plan / tasks / base | 358×40 | 分段选择器，选中＝**浅底黑字**（反白） |
| `Btn/Action` | `kind` = light / outline / go / stop / confirm × `state` = normal / disabled | 112×40 | 10 个变体 |
| `Btn/Status` | `kind` = launch / stop | 120×48 | 双行（小英文 + 大中文） |
| `Chip/Status` | `kind` = idle / active / success / warn | 80×32 | 点 + 文字 |
| `Bar/Progress` | `style` = block / ticks | 358×12 | 实心填充 / 刻度块 |
| `Card/Task` | `state` = launching / idle / done | 358×150 | 视觉区 + 时间 + 芯片 + 动作 + 进度 |
| `Card/Knowledge` | `state` = new / review | 358×500 | 卡图 + 正文 + 编号 + 芯片 |

**全部 158 处颜色/尺寸引用都绑到了变量**（渲染报告：`158 bound, 0 literal`）。
改 `SP/Color` 里任一变量，所有组件与后续实例同步变——这正是你"验证视觉、还会继续改"最需要的性质。

### 3.1 文字属性：哪些有、哪些**刻意没有**

| 组件集 | 文字属性 | 为什么 |
|---|---|---|
| `Btn/Action` | ✅ `Label`（10 个变体全绑） | 按钮文案每次都要改 |
| `Card/Knowledge` | ✅ `Body`（正文）、`Code`（编号） | 两个变体共用同一张卡的正文/编号 |
| `Seg/Bar` | ❌ | 文案由变体决定（plan/tasks/base） |
| `Chip/Status` | ❌ | 同上（idle/active/success/warn → 待机/执行中/…） |
| `Btn/Status` | ❌ | 同上（launch/stop → 发射/终止） |
| `Card/Task` | ⏳ 待补 | 时间文案可由实例直接双击改 |
| `Bar/Progress` | ❌ | 无文字 |

**这条是实测出来的，不是设计偏好**：跨变体共享的文字属性**只有一个值**。
我一开始给 Chip 和 Btn/Status 也加了文字属性，结果四个 chip 全变成「待确认」、两个状态按钮全变成「终止」——
因为给其中任一变体赋值，会同步到全部变体。所以**"文案由变体决定"的地方就不能用文字属性**，已撤掉这些属性并逐变体还原了文案。

## 四、尺寸标准化：改了哪些数

**你的原值我没能全留**——标准化意味着把离群值收到栅格上。逐条列出（出现次数按手摆板统计）：

| 原值 | 标准值 | 出现 | 说明 |
|---|---|---|---|
| 361（宽） | **358** | 6 | 与线框稿 `content/w` 统一（390 − 16×2） |
| 335（知识卡宽） | **358** | 1 | 与任务卡对齐，两张卡同宽 |
| 30（高） | **32** | 8 | 统一到 `h/sm` |
| 45（高） | **48** | 6 | 统一到 `h/lg` |
| 61（按钮宽） | **112** | 6 | 收进 `Btn/Action` 的 md 档 |
| 113 / 117 / 121 / 124 | **120** | 4 类 | 同一个「任务状态按钮」的四种宽度 → 一个 |
| 79 / 81 / 106 | **80** | 3 类 | 芯片宽度 → 一个 |
| 115 + 间距 3 | **114 + 间距 4** | 6 | 分段落栅格：2+114+4+114+4+114+2 = 358 ✓ |
| 227（卡内进度条） | **326** | 2 | 卡片内宽 − 左右各 16 |
| 59（卡内视觉区高） | **56** | 2 | 落栅格 |

> 这些都是 1–5 px 级微调，不改视觉观感；但从此拼界面不用再逐处对坐标。
> **如果你更想保留某个原值**，改组件里的尺寸即可——令牌是变量，组件的尺寸是固定值，不冲突。

## 五、怎么用

```
1. 从 Assets 面板拖组件 → 改变体属性（右栏）→ 改文字属性（若有）
2. 改颜色：动 SP/Color 里的变量，所有实例跟着变（不要手动改实例填充）
3. 新组件：先复用上面 7 个；确实需要新的，再按同一套令牌做
4. 拼页面：内容宽用 358，左右安全边距 16（与线框稿一致）
```

**不要做的事**：

- 不要再从手摆板复制矩形去拼界面（会带回 361/30/45 这些离群值）；
- 不要在实例里手动改颜色（改用变量，否则改主色时会漏掉这些实例）；
- 不要给"文案由变体决定"的组件加文字属性（见 3.1 的原因）。

## 六、还没做的（等你继续改完视觉再定）

| # | 项 | 说明 |
|---|---|---|
| 1 | `Card/Task` 的文字属性 | 时间 / 芯片文案，需先把文字层统一命名 |
| 2 | `Icon/Btn`（28×28 汉堡、勾选、三角） | 手摆板里是 4 个独立矩形，尚未归纳成组件 |
| 3 | 时钟 + 信号指示（`12:00 PM` + 信号条） | 尚未归纳 |
| 4 | 「进度条 提案1」的斜纹填充 | 斜纹需要贴图或 pattern，JSX 做不了；现用 `style=ticks`（竖刻度块）近似 |
| 5 | 事件卡 / 媒体行（`事件：XXXXX` + 播放键） | 尚未归纳 |
| 6 | 组件变体的排版 | 组件集内自动布局按 Figma 默认排，未逐个调过位置 |

这些等你视觉定稿后再做，避免现在做完又返工。

```powershell
# 渲染 _kit.jsx → node to-component 每个变体帧 → component combine 合并 → node reparent 进画板
```

### 渲染时踩到的两个坑（已固化）

| 坑 | 正解 |
|---|---|
| 组件名里的 `/` 会干扰变体解析，生成垃圾属性 `Property 1` | 合并前变体帧只写 `prop=value`，**组件集名**才带 `/`；合并后用 `node rename` 修正 |
| `component combine` 会把变体移出原父级 | 合并后用 `node reparent <子> <父>` 移回画板（**保留画布位置**） |
