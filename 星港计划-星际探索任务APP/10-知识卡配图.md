## 一、这批图是什么

为 [09-内容库-知识卡](09-内容库-知识卡.md) §四 已写全的 **13 个主题 × 6 张 = 78 张知识卡**，每张配一张主视觉插图。

| 项 | 值 |
|---|---|
| 张数 | **78**（覆盖全部已写全的卡片，一张不缺） |
| 风格 | 像素 / 复古未来主义（32-bit retro-futurism） |
| 色板 | 严格取自 [06](06-界面规范.md) §五 令牌与色板 |
| 基准尺寸 | `512 × 768`（2:3 竖版，真像素栅格） |
| 放大版 | `1536 × 2304`（最近邻 3 倍，保留硬像素边） |
| 模型 | Qwen-Image 2.1（`qwen-image-2.1-UC-Q4_K_M.gguf`） |
| 采样 | euler / simple · cfg 1.0（官方推荐路径）· 25 步 · 768×1152 生成后重采样 |

### 色板锚点（与 App 统一，不是随手配色）

| 用途 | 色值 | 出处 |
|---|---|---|
| 背景（夜 / 深夜） | `#101A2C` / `#0A1020` | 07 §4.2 夜 · 深夜相位 |
| 中间调（高光） | `#3A5A80` | 07 §4.2 夜相位高光 |
| 强调（琥珀） | `#E8A468` | 07 §4.2 晨相位强调色 / §4.3 `accent/amber` |
| 亮部（奶油） | `#F2E4C9` | 07 §4.2 昼相位高光 |

> **为什么用暗底**：07 §4.2 规定「强调色占屏面积 ≤8%，因为夜里光本来就少，铺开就没重点了」。
> 这批图统一走**深空暗底 + 单一琥珀光源**，嵌进暗色卡片后不会抢 HUD 的重点色。

## 二、尺寸与用法

```
assets/knowledge-cards/
├── <ID>.png            512 × 768     ← 集册网格缩略 / 卡片上半部嵌入
├── <ID>_x3.png        1536 × 2304    ← 详情页全宽大图（真像素，不糊）
├── contact-sheet.png                  ← 78 张总览（评审用）
└── manifest.json                      ← 卡片 ↔ 文件 ↔ 提示词 ↔ seed 对照表
```

| 用在哪 | 用哪个 | 建议做法 |
|---|---|---|
| 卡片集册网格（[06](06-界面规范.md) §六「组件清单」的知识卡缩略） | `<ID>.png` | 裁上半部，外层套 T0–T3 四色边 |
| 知识卡详情页（07 §二 #13） | `<ID>_x3.png` | 顶部通栏，`image-rendering: pixelated` |
| 结算抽屉里的卡片弹出 | `<ID>.png` | 先显 512 版，加载完再换 `_x3` |

**关键：显示时必须带 `image-rendering: pixelated`**（或 Flutter 的 `FilterQuality.none`），
否则浏览器/引擎会做双线性插值，像素块会被抹成模糊的假照片。这跟 [04](04-数值与养成.md) §八「无障碍与降级」是一条底线。

### 构图约定

所有图都是**主体居中偏上、下半部留深空暗场**。原因：知识卡详情页的版式是
「标题 + 大号数字 + 正文」压在图片下方，下方留白正好承接文字，不需要额外加渐变遮罩。
需要更亮/更暗时，用 [06](06-界面规范.md) §五 的 `bg/canvas` 加一层 0→100% 的线性渐变即可。

## 三、怎么重跑 / 微调

生成脚本在工作区 `_comfy/` 下（不在本目录，避免污染项目）：

| 文件 | 作用 |
|---|---|
| `_comfy/cards.json` | 从 11 §四 解析出的 78 张卡结构化数据 |
| `_comfy/prompts.py` | 风格锚点 + 78 条专属视觉母题 + 按系列兜底 |
| `_comfy/qwen_gen.py` | ComfyUI 客户端（工作流提交 / 轮询 / 下载 / 3 张并行排队） |
| `_comfy/gen_all.py` | 批量入口：78 张 → 放大 → manifest → 总览图 |

```powershell
# 前提：ComfyUI 跑在 127.0.0.1:8188
cd F:\deepseek\作业\_comfy
& "E:\Comfy-Desktop\ComfyUI-Installs\image\ComfyUI\.venv\Scripts\python.exe" gen_all.py
```

- **断点续跑**：已存在的 `<ID>.png` 自动跳过，中断后重跑即可。
- **改单张**：改 `prompts.py` 里 `MOTIF["<ID>"]` 那句，删掉对应 png 重跑。
- **改 seed**：`gen_all.py` 的 `seed_for()` 由卡片编号哈希得出（同一编号永远同一张），要换图就改这里加偏移。
- **改风格**：只改 `prompts.py` 顶部的 `STYLE` 常量，78 张会一起变。

## 四、已知限制（评审时请重点看这里）

| # | 限制 | 说明 |
|---|---|---|
| 1 | **像素栅格不是整数对齐的** | 生成模型画的是「像素风纹理」，不是真正的 64×96 网格。图上像素块大小会有 ±1px 抖动。影响：贴进像素 UI 时，和 UI 自己的像素网格不严格对齐。 |
| 2 | **T0–T3 稀有度没有视觉差异** | 目前只靠 07 §5 规定的「四色边」区分层级，图像本身不表达稀有度。若要「深空卡更炫」，需要给 T2/T3 单独跑一版更亮的光效提示词。 |
| 3 | **个别图可能跑偏** | 78 条母题是手写的，模型仍可能忽略其中一部分（比如要求「两张月亮并排」只画了一张）。`contact-sheet.png` 一次看全，逐张挑出来后按 §三 改提示词重跑。 |
| 4 | **没有生成封面/系列徽记** | 这批只做单卡插图。6 个系列头图、集册封面、T0–T3 徽章还没做。 |
| 5 | 生成成本 | 单张约 44 秒（RTX 4070 Laptop 8G，Q4_K_M 量化），78 张约 58 分钟。改提示词重跑整批是可行但不算快的操作。 |

## 五、和 Z-Image-Turbo 的对比（为什么选 Qwen）

两台模型都在本机，同一套提示词实测：

| 项 | Z-Image-Turbo | **Qwen-Image 2.1** |
|---|---|---|
| 单张耗时（768×1152） | 18 秒 | 44 秒 |
| 像素块规整度 | 更整齐（块更硬） | 细像素，块略软 |
| **画面层次 / 细节** | 平、块状、色阶少 | **环带层次、环形山、尘埃结构都在** |
| 构图留白 | 不可控（经常居中顶满） | **稳定上方主体 + 下方暗场** |
| 语义准确度 | 一般 | **明显更好** |

**结论**：Z-Image 快 2.4 倍、像素更「硬」，但 Qwen 的细节与语义准确度对知识卡更关键
（知识卡要让人「看出这是什么天体」）。所以定稿用 Qwen；若后续要补 138 张待写卡、且只需要氛围图，可切回 Z-Image 换速度。
