# 08 · 数据模型与技术方案

> 原则：**本地优先**（无账号也能完整使用）、**无云依赖**（v1 不做账号体系）、**可导出**（数据属于用户）。
> 三维渲染的选型与性能目标见 [10 §十一](10-星球地图与三维场景.md)。

---

## 一、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 三维渲染 | **WebView + three.js（WebGL2 基线，WebGPU 可选加速）** | 三维仅为顶部 358×180 视窗；详见 [15](15-顶部三维渲染可行性评估.md) |
| 平台 | iOS + Android（原生外壳 + 单个 WebView 三维视口） | 闹钟/通知/存储仍用原生 |
| 本地存储 | SQLite（结构化）+ 文件（贴图/模型） | 查询与迁移都稳 |
| 状态管理 | 单向数据流 + 事件溯源（Session 为不可变事件） | 目录回滚与统计都靠事件 |
| 通知/闹钟 | 平台原生（`UNCalendarNotificationTrigger` / `AlarmManager`） | 精确闹钟必须原生 |
| 同步 | **v1 不做**；导出 JSON / CSV | 见 §六 |

### 1.1 三维方案决策

> **2026-10 修订**：三维范围已从「全屏星球地图」收缩为「顶部 358×180 视窗」（IA v2），
> 渲染负荷降至原规划的 1/5（稳态 3.2 万三角面）。完整评估见 [15-顶部三维渲染可行性评估](15-顶部三维渲染可行性评估.md)。

| 方案 | 包体增量 | 首帧 | 覆盖率 | 建议 |
|---|---|---|---|---|
| **A · WebView + three.js（WebGL2）** | ≈ 3.2 MB | 200–600 ms（预热+占位图可无感） | >99% | ✅ **推荐基线** |
| **B · 同上 + `WebGPURenderer`（TSL 同一套着色器，自动回退）** | 同 A | 同 A | 同 A | ✅ 零成本叠加，**但不得进验收门** |
| C · 原生 Metal + GLES | ≈ 0.5 MB | <100 ms | 100% | 仅当三维扩回全屏再考虑 |
| D · 原生 WebGPU（Dawn） | ≈ 5–10 MB | 快 | 取决于 Dawn | ❌ 3.2 万面不值得 |
| E · 2.5D 预渲染转盘 + 设施精灵 | ≈ 1–2 MB | 几十 ms | 100% | ⚠️ 降级备选（触发条件见 15 §7.3） |
| F · Unity URP / Godot 4 | 30–60 MB / 15–25 MB | 1–2 s | 100% | ❌ 为 3.2 万面付此代价不划算 |

**结论**：
1. **性能不是瓶颈**——GPU 单帧 0.35–0.93 ms，每帧总预算 2.0–5.5 ms（60fps 需 16.7 ms）；
2. **WebGPU 不作为验收依赖**，因 iOS ≤18 无 WebGPU、Android WebView 默认开启与否待实测；
3. 真正的工程风险是 **WebView 首帧、内存、上下文丢失**（见 15 §六），三者都有成熟对策；
4. 必须先在 6 机型上跑 S0 实测（`spike/planet-spike.html`），过 §7.2 决策门才进入实现。

## 二、数据模型（SQLite）

### 2.1 核心实体

```sql
-- 指挥官（单行表）
commander(
  id INTEGER PK, code_name TEXT, call_sign TEXT,
  planet_name TEXT, skin TEXT, hud_theme TEXT,
  xp_total INTEGER, level INTEGER,
  rc_total INTEGER,
  created_at INTEGER, last_active_at INTEGER,
  ai_mode TEXT,              -- 'terse' | 'human' | 'data'
  disturbance_enabled INTEGER DEFAULT 1,
  light_follow TEXT,         -- 'device' | 'fixed'
  location_mode TEXT,        -- 'auto' | 'manual'
  lat REAL, lon REAL, city TEXT
);

-- 机构
agency(
  id INTEGER PK, name TEXT, code TEXT, domain_color TEXT, emblem TEXT,
  slogan TEXT, template TEXT,          -- MED/KIT/.../GEN/CUSTOM
  state TEXT,                          -- draft|active|idle|parked|archived
  echelon INTEGER,                     -- 0..4 编制
  anchor_lat REAL, anchor_lon REAL,    -- 球面锚点（度）
  occupancy INTEGER,                   -- 1..3 格
  total_sessions INTEGER, total_minutes INTEGER,
  distinct_days INTEGER, kinds_used INTEGER,
  created_at INTEGER, parked_at INTEGER
);

-- 计划
program(
  id INTEGER PK, agency_id INTEGER FK, name TEXT,
  period_days INTEGER, period_kind TEXT,   -- '7d'|'14d'|'21d'|'30d'|'8w'|'custom'
  freq_kind TEXT,                           -- 'daily'|'weekly_n'|'alternate'|'dow'
  freq_n INTEGER, freq_dow TEXT,            -- '1,3,5'
  rest_days TEXT, tier TEXT,                -- 'light'|'standard'|'deep'
  strict INTEGER DEFAULT 0,
  state TEXT,                               -- 'active'|'paused'|'completed'|'reset'
  cycle_index INTEGER,                      -- 第几轮
  started_at INTEGER, ended_at INTEGER,
  prog_current INTEGER DEFAULT 0,           -- 当期进度（格）
  prog_target INTEGER
);

-- 任务
mission(
  id INTEGER PK, program_id INTEGER FK, agency_id INTEGER FK,
  name TEXT, kind TEXT,                     -- 'timed'|'count'|'bool'
  target_minutes INTEGER, target_count INTEGER,
  schedule_dow TEXT, schedule_slot TEXT,     -- 'morning'|'anytime'|'night'
  exec_mode TEXT,                            -- 'ignite'|'window'|'log'
  window_time TEXT,                          -- 'HH:mm' 用于 window
  window_days TEXT, snooze_max INTEGER,
  min_ratio REAL DEFAULT 0.6,
  remind_at TEXT, remind_on INTEGER,
  sort INTEGER, archived INTEGER DEFAULT 0
);

-- 执行记录（不可变事件，永不删除）
session(
  id INTEGER PK, mission_id INTEGER FK, agency_id INTEGER FK, program_id INTEGER FK,
  started_at INTEGER, ended_at INTEGER, elapsed_s INTEGER,
  target_s INTEGER,
  result TEXT,          -- 'success'|'pass'|'aborted'|'window_confirmed'|'window_late'|'window_missed'
  day_index INTEGER, day_seq INTEGER,        -- 当日第几次（用于递减）
  xp_awarded INTEGER, rc_awarded INTEGER,
  decay_factor REAL, tier_factor REAL,
  is_min_ratio INTEGER,
  created_at INTEGER
);

-- 研究成果（知识卡持有）
archive_item(
  id INTEGER PK, card_id TEXT,             -- 'TIM-001'
  series TEXT, tier TEXT,
  obtained_at INTEGER, source_session INTEGER FK,
  read_at INTEGER, is_read INTEGER,
  is_favorite INTEGER
);

-- 星图节点（永久）
starmap_node(
  id INTEGER PK, kind TEXT,                -- 'agency'|'program'|'realstar'|'named'|'comet'|'mornstar'|'plot'
  ref_id INTEGER, label TEXT, lat REAL, lon REAL,
  unlocked_at INTEGER, meta TEXT
);

-- 公共设施
facility(
  id INTEGER PK, key TEXT,                 -- 'tower'|'life'|'power'|'observ'|'archive'|'dock'|'green'|'radar'
  level INTEGER DEFAULT 0,                 -- 0..5
  unlocked_at INTEGER
);

-- 扰动记录
disturbance(
  id INTEGER PK, tier TEXT,                -- 'T1'|'T2'|'T3'|'T4'
  name TEXT, session_id INTEGER FK,
  xp_bonus_ratio REAL, card_granted INTEGER,
  rolled_at INTEGER,
  scope TEXT,                              -- 'day' 生效范围
  expires_at INTEGER
);

-- 保底计数
pity(
  id INTEGER PK, key TEXT,                 -- 't3'|'t4'
  counter INTEGER, threshold INTEGER,
  last_reset_at INTEGER
);

-- 里程碑/快照/彩蛋
milestone(id INTEGER PK, key TEXT, unlocked_at INTEGER, meta TEXT);
snapshot(id INTEGER PK, taken_at INTEGER, json TEXT);   -- 每周 1 张，保留 13
egg_log(id INTEGER PK, key TEXT, fired_at INTEGER, meta TEXT);
settings(key TEXT PK, value TEXT);
```

### 2.2 不可变性规则

| 规则 | 说明 |
|---|---|
| `session` 只增不删 | 删除机构 → `agency.state='archived'`，`session` 全保留 |
| 重置计划不改历史 | 新建 `program` 行（`cycle_index+1`），旧行 `state='reset'` |
| XP 不回退 | `commander.xp_total` 只增；任何机制不得写入更小值（**数据库层加 CHECK 约束**） |
| 星图只增 | `starmap_node` 无 DELETE 权限 |

**建议在 DB 层加约束**，而不是只靠业务层：

```sql
CREATE TRIGGER trg_xp_monotonic BEFORE UPDATE ON commander
WHEN NEW.xp_total < OLD.xp_total
BEGIN SELECT RAISE(ABORT, 'xp must not decrease'); END;
```

## 三、关键算法

### 3.1 光照相位计算（真实天文）

```
输入：unix 时间 t、纬度 lat、经度 lon、时区偏移 tz
1) 儒略日 JD = t/86400 + 2440587.5
2) 太阳平黄经 L、平近点角 g（标准低精度太阳位置算法，误差 <0.01°）
3) 太阳赤纬 δ = asin(sin(ε) · sin(L))，ε = 23.4397°
4) 时差 EqT（分钟）：由 L 与 g 求得，范围约 ±16 分钟
5) 真太阳时 TST = UTC小时 + lon/15 + EqT/60
6) 时角 H = 15° × (TST − 12)
7) 太阳高度角 alt = asin( sin(lat)sin(δ) + cos(lat)cos(δ)cos(H) )
8) 相位判定：
     alt >   0°  → day
   -6° ≤ alt ≤ 0° → dawn（上午）/ dusk（下午，按 H 符号）
  -12° ≤ alt < -6° → dusk 深段 / night 起始
  -18° ≤ alt < -12° → night
     alt < -18° → deep
   极昼/极夜：|lat| 高且当日 δ 与该半球同号 → polar
```

**精度要求**：相位切换时刻与天文年历误差 ≤ **15 分钟**（第 10 章验收判据 7）。

**离线可用**：全部本地计算，不请求网络。缓存当日日出/日落一次即可。

### 3.2 计时（防漂移）

```
start = monotonicClock()          // 用单调时钟，不用墙钟
// 每秒前台 tick 只用于重绘，不用于累加
elapsed = monotonicClock() - start
剩余 = target - elapsed
```

| 场景 | 处理 |
|---|---|
| 切后台 | 保存 `start` + `wall_clock_at_start` |
| 回前台 | `elapsed = 用墙钟差`，若与单调时钟差异 > 2s 以墙钟为准（防设备休眠停表） |
| 进程被杀 | 从 DB 读回未完成 Session（标记 `interrupted`），允许用户选择"计入中止"或"丢弃" |
| 系统时间被改 | 检测回拨：若墙钟倒退 > 60s，只用单调时钟并标记该 Session `clock_anomaly` |

### 3.3 XP / 递减 / 扰动结算

```pseudo
function settle(session):
  decay  = DECAY[min(session.day_seq, len(DECAY)) - 1]
  tierK  = {light: 0.8, standard: 1.0, deep: 1.3}[program.tier]
  base   = XP_IGNITE(session.target_min, session.ratio)
  xp     = round(base * decay * tierK)
  rc     = max(1, round(RC_BASE * decay))

  if disturbance_enabled:
    tier = roll_disturbance(pity, day_limit, month_cap)
    xp   = apply_bonus(xp, tier)        // 当日生效，取当日最高，不叠加
    if tier in [T3, T4]: grant_card(rare=true)   // 每日 ≤1
  grant_card(per_rules)                 // 普通概率
  commit_immutable(session, xp, rc)
```

### 3.4 锚点分配（球面不重叠）

```
全球锚位 = 按 12° 纬度带 × 12° 经度格生成候选点（≈91 个）
新机构落位：
  1) 排除已被占用（含 3 格占地的邻域）
  2) 偏好靠近同域色/同模板的已有设施（聚类，视觉更整齐）
  3) 避免落在默认视角的背面（首次成立必须可见）
  4) 共存时保证最小 2.5° 经度间隔
用户手动选址：吸附到最近的合法锚位（带 0.15s 吸附动画）
```

## 四、闹钟与通知（平台细节）

| 平台 | 机制 | 注意 |
|---|---|---|
| iOS | `UNCalendarNotificationTrigger`（重复）+ 关键闹钟（iOS 26+ AlarmKit 可用则优先） | 无静默降级：必须用户授权通知 + 声音 |
| Android | `AlarmManager.setExactAndAllowWhileIdle` + `SCHEDULE_EXACT_ALARM` 权限 | 需引导电池白名单；国产 ROM 差异大 |
| 双链路兜底 | ① 本地精确闹钟 ② 系统日历镜像事件（带提醒） | ② 作为第二链路，无需网络 |
| 云端兜底 | v1 不做（无账号） | P5 再议 |
| 自检页 | 显示最近 3 次触发的"设定时间 vs 实际触发时间"偏差；连续 2 次 >2 分钟 → 提示白名单 | 把不可靠变得可见，比假装可靠更诚实 |
| 通知文案 | 不写"该起床啦"，写「07:00 窗。」 | 见 09 文案规范 |

## 五、埋点与指标体系

### 5.1 事件表（15 个核心事件）

| 事件 | 属性 | 用途 |
|---|---|---|
| `app_open` | 形态（map/list）、相位、来源 | 打开分布、形态偏好 |
| `map_rotate` | 时长、角度 | 地图是否被使用（关键：若无交互说明地图是负担） |
| `facility_tap` | agency_id、命中/未命中 | 判据 1（可点中率 ≥95%） |
| `panel_open` | agency_id、层（L1/L2/L3）、来源 | 面板使用路径 |
| `session_start` | 形态、执行方式、任务 | 最短路径验证 |
| `session_end` | result、elapsed、ratio、xp、rc | 主指标 |
| `settle_view` | 停留时长、卡是否展开 | 结算页停留 2–6s 判据 |
| `card_read` | card_id、时长、是否到底 | 完整阅读率 ≥60% |
| `card_extend_tap` | card_id | 延伸点击 ≥20% |
| `card_error_report` | card_id、内容 | 错误率监控 |
| `disturbance_roll` | tier、是否保底触发 | 概率与保底校验 |
| `disturbance_off` | — | 关闭率 ≤25% |
| `view_switch` | 方向、耗时 | 双形态切换体验 |
| `facility_upgrade` | key、level、耗时 | 扩建节奏 |
| `window_confirm` | result、延迟分钟 | 早起真实性（关键诚实指标） |

### 5.2 计算指标

| 指标 | 公式 |
|---|---|
| WEOM（北极星） | Σ(session.elapsed where result=success) / 周活跃指挥官数 |
| 点火完成率 | success / (success + aborted) |
| 窗口确认率 | window_confirmed / 全部触发窗口 |
| 知识卡完整阅读率 | card_read(到底) / 发放卡数 |
| 形态偏好 | app_open 中 map / list 比例 |
| 地图参与度 | 有 map_rotate 的会话 / 总会话（**<20% 说明地图是装饰**） |

## 六、隐私与数据归属

| 项 | 做法 |
|---|---|
| 定位 | **可选**；拒绝则用手动城市（误差 <30 分钟） |
| 上传 | v1 **不上传任何数据**；无账号、无云 |
| 导出 | JSON（全量）+ CSV（记录），一键导出 |
| 删除 | 本地清空 + 导出提示（先给用户一份，再删） |
| 分析 | v1 可完全关闭遥测；开启时不含任何内容文本，只有事件名与计数 |
| 权限 | 只申请：通知、闹钟（Android）、定位（可选）、健康数据（P5，可选） |

## 八、技术风险

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| 1 | 三维在低端机上掉帧 | 中 | 高 | 三档渲染 + 自动降档 + 低档仅剪影（第 10 章 §十二） |
| 2 | Android 闹钟不准 | 高 | 高 | 双链路 + 自检页 + 诚实呈现（不倒扣） |
| 3 | 相位光照算错 | 低 | 中 | 单测覆盖 10 组已知日出日落；误差 >15min 即回归失败 |
| 4 | 包体过大 | 中 | 中 | 贴图压缩（ASTC）、模型图集、按需下载高模（P5） |
| 5 | 计时被系统休眠打断 | 中 | 中 | §3.2 的墙钟校正 + 异常标记 |
| 6 | 球面锚点冲突 | 低 | 低 | §3.4 的候选点 + 邻域排除（91 位足够） |
| 7 | 知识卡错误 | 中 | 高 | 双人核对 + `verified_at` + 48h 纠错通道 |
