# 04 · 数值与成长经济

> 数值只服务三件事：**让积累变多、让中断不痛、让随机不失控**。
> 所有数字都可用脚本复算（附录 A 给了公式与代码）。

---

## 一、三种东西，用途完全不重叠

| 名称 | 界面写法 | 世界名 | 获得 | 用途 | 可否失去 |
|---|---|---|---|---|---|
| 推进值 | `XP` | 推进值 | 每次成功执行 | 只用于**累计**，决定指挥官等级 | ❌ 永不回退 |
| 研究成果 | `RC` | 研究成果 | 成功执行 / 节点结算 / 稀有扰动 | 决定**知识卡**的获取与集册进度 | ❌ 永不回退 |
| 星图节点 | — | 星图 | 首次达成某条件时自动点亮 | 永久记录，**无数值作用** | ❌ 永不 |

**三条硬规则**：

1. **没有任何东西可以被花掉**。没有商店、没有消耗、没有"用 XP 换建筑"。星港扩建看的是**门槛**，不是余额（见 [05](05-星港养成与个性化.md)）。
2. **RC 与 XP 不成正比**。RC 更看"类型与难度"，XP 更看"时长"。这避免用户为了攒 RC 去刷长时长的低价值任务。
3. **随机扰动只影响"呈现与稀有度"，永不影响 XP 主体数值**。T3 的加成是当日结算页面的显式加成，不是暗改单价。

## 二、XP 产出表（唯一真相源）

### 2.1 点火（番茄钟专注）

| 档位 | 达标（≥100%） | 及格线（60–99%） | 中止（30–59%） | RC |
|---|---|---|---|---|
| 15 分钟 | 24 | 15 | 7 | 1 |
| 25 分钟 | 40 | 24 | 12 | 2 |
| 45 分钟 | 72 | 43 | 22 | 3 |
| 60 分钟 | 96 | 58 | 29 | 4 |
| 自定义 | `round(1.6 × 分钟)` | ×0.6 | ×0.3 | 每 20 分钟 +1（向上取整） |

**判定阈值**：达标 = 实际时长 ≥ 目标 × 1.0；及格线 = ≥ 0.6（最小完成线，可关）；中止 = 0.3–0.59；< 0.3 不计。

### 2.2 发射窗口（闹钟）

| 情况 | XP | RC | 说明 |
|---|---|---|---|
| 30 分钟内确认 | 30 | 2 | 记为 `window_confirmed` |
| 30–120 分钟确认 | 15 | 1 | 记为 `window_late`，仍算成功 |
| 未确认 | 0 | 0 | 记为 `window_missed`，**不扣任何已有数值** |
| 天文晨前确认（太阳高度 < −18°） | +20 额外 | +1 | 发放「晨星」标记（真实成就） |
| 贪睡 1 次 | ×0.8 | — | 贪睡 2 次 ×0.6 |

### 2.3 自由记录

| 情况 | XP | RC | 说明 |
|---|---|---|---|
| 布尔（做了） | 10 | 1 | 固定值，不随时长变化 |
| 计数（如 20 个单词） | `round(0.5 × 个数)`，上限 40 | 每 20 个 +1 | 防刷上限 |

### 2.4 计划与节点

| 事件 | XP | RC | 说明 |
|---|---|---|---|
| 当日全部任务完成 | +20 | +2 | 一次性，当天只给一次 |
| 计划节点达成（小型） | +80 | +8 | 周期 ≥7 天的小节点 |
| 计划节点达成（中型） | +160 | +15 | 周期 ≥14 天 |
| 计划完成（全部节点） | +300 | +30 | 结算页发放，**保底 1 张知识卡** |
| 一整个机构当天全清 | +15 | +1 | 跨机构额外的小奖励 |

### 2.5 难度档（只调 XP 系数，不调判定）

| 档 | XP 系数 | 卡池稀有度上限 | 适用 |
|---|---|---|---|
| 轻量 | ×0.8 | T0–T1 | 恢复期、生病、忙碌周 |
| 标准（默认） | ×1.0 | T0–T2 | 大多数人 |
| 深空 | ×1.3 | T0–T3 | 高压期、冲刺备考 |

**注意**：难度档不改变"是否算完成"。用户调低难度**不会**降低任何历史记录。这是防止"状态差→不敢降难度→干脆不打开"的关键。

## 三、同日递减（防刷的核心机制）

同一天内，同一机构的第 N 次成功执行，XP 按下表衰减：

| 当日第 N 次 | 系数 | 25 分钟档实得 |
|---|---|---|
| 1 | 1.00 | 40 |
| 2 | 0.80 | 32 |
| 3 | 0.60 | 24 |
| 4 | 0.40 | 16 |
| 5 | 0.30 | 12 |
| 6+ | 0.20 | 8 |

**规则细则**：

| 项 | 规则 |
|---|---|
| 递减按机构独立计算 | 体能署第 2 次衰减不影响学研所第 1 次 |
| 必须**明示** | 结算显示 `+16（今日递减）`，绝不做隐藏衰减 |
| RC 同步递减 | 系数同上，向上取整后最低 1（不能归零） |
| 扰动 roll 不受影响 | 但**稀有 roll（T3/T4）每天上限 1 次**（见 06） |
| 不做负值 | 第 6 次仍给 +8，永不为 0。理由：有人就是一天做 8 件事，不该被系统惩罚 |

**设计意图**：递减不是为了惩罚，而是为了让"刷任务抽卡"这条路不划算——**把它做得没有吸引力，而不是把它堵死**。

## 四、指挥官等级

### 4.1 曲线公式

```
本级所需 gap(Lv.n) = 240 + 40 × (n − 1)          n = 1,2,3,…
累计门槛 T(Lv.n)   = Σ_{k=1}^{n−1} gap(k)          T(Lv.1) = 0
```

| 等级 | 本级所需 | 累计门槛 |
|---|---|---|
| Lv.1 | 240 | 0 |
| Lv.2 | 280 | 240 |
| Lv.3 | 320 | 520 |
| Lv.5 | 400 | 1,200 |
| Lv.10 | 600 | 3,600 |
| Lv.15 | 840 | 7,000 |
| Lv.20 | 1,000 | 11,400 |
| Lv.25 | 1,200 | 16,800 |
| Lv.30 | 1,400 | 23,200 |

**MVP 封顶 Lv.30**（P5 再扩到 Lv.40）。曲线是线性的（每级 +40），不是指数——**理由见下**。

### 4.2 为什么用线性曲线，不用指数

| 曲线 | 问题 |
|---|---|
| 指数/幂律（游戏常用） | 中期开始每级要几个月，用户看不到等级变化 → 反馈断裂 |
| 线性 | 每级成本增幅固定（+40），**到后期升级反而更快**（因为周产出在增长） |

**结论**：自律产品的等级是"进度尺"，不是"消耗坑"。用户后期变强（习惯稳定）时，升级应该更容易，而不是更难。

### 4.3 五类用户画像的到级时间（脚本实测）

| 画像 | 周 XP | 到 Lv.3 | 到 Lv.10 | 到 Lv.20 | 到 Lv.30 |
|---|---|---|---|---|---|
| 轻度（每天 1×25 分钟） | 280 | 1.9 周 | 12.9 周 | 40.7 周 | 82.9 周 |
| 标准（每天 2×25 分钟 + 1 次记录） | 546 | 1.0 周 | 6.6 周 | 20.9 周 | 42.5 周 |
| 早起（1 窗 + 1×45 分钟） | 616 | 0.8 周 | 5.8 周 | 18.5 周 | 37.7 周 |
| 重度（每天 4×25 分钟） | 784 | 0.7 周 | 4.6 周 | 14.5 周 | 29.6 周 |
| 冲刺（每天 6 次混合） | 1,393 | 0.4 周 | 2.6 周 | 8.2 周 | 16.7 周 |

**判据**：
- Lv.3 应在**第 1–2 周**内达成（首月有 2–3 次升级）→ 上表全部满足；
- Lv.30 不应在 1 年内达成（保持长线空间）→ 轻度用户 83 周 ≈ 1.6 年，合格；
- 若实测"轻度用户 2 周内达不到 Lv.3"→ 下调 gap 基数 240 → 200。

### 4.4 等级权益（只解锁表达，不解锁数值）

| 等级段 | 解锁 |
|---|---|
| Lv.1–4 | 基础 HUD、默认星球涂装 |
| Lv.5 | 星球可命名、设施标签可改名 |
| Lv.8 | 第二套星球涂装、HUD 主题（亮/暗手动锁定） |
| Lv.12 | 星图缩放层级 +1、星座连线开关 |
| Lv.16 | 第三套涂装、设施铭牌自定义 |
| Lv.20 | 舱内视图（第一人称视角看星港，纯观赏） |
| Lv.25 | 第四套涂装、星空亮度调节 |
| Lv.30 | 旗舰徽记灯效 |

**没有任何等级权益是"更多 XP"或"更快升级"**。升级带来的只有"看起来不一样"。

## 五、防刷与中立性（本章最重要的一节）

### 5.1 为什么必须防刷

产品命题是"让现实行动有价值"。一旦 **投入产出比可以通过操作技巧优化**，用户就会优化操作而不是优化生活——这是所有游戏化自律产品死亡的方式（Habitica 的刷怪问题）。

### 5.2 五道防线

| # | 防线 | 机制 |
|---|---|---|
| 1 | 同日递减 | §三，第 6 次只有 20% |
| 2 | 稀有 roll 日限 | T3/T4 每天最多 1 次（见 06 §四） |
| 3 | RC 不等比 | RC 看类型/难度，不看时长总量 |
| 4 | 无消费出口 | 不能把 XP 换成任何东西，因此没有"刷完买什么"的动机 |
| 5 | 机构门槛看**广度与航时** | 设施升级要求"≥2 类执行方式""≥3 个不同日期"，纯刷一天的无效 |

### 5.3 中立性承诺（写进设置页）

> **同一个 25 分钟，在哪个机构、哪个等级、哪种涂装下做，得到的推进值一样。**

具体表现为：

| 场景 | 是否影响 XP |
|---|---|
| 机构编制 I0 vs I4 | ❌ 不影响 |
| 指挥官等级高 vs 低 | ❌ 不影响 |
| 买了 Pro vs 免费 | ❌ 不影响 |
| 有涂装 vs 无涂装 | ❌ 不影响 |
| 连续天数长 vs 短 | ❌ 不影响（**没有连击加成**） |
| 难度档 | ✅ 影响（×0.8 / ×1.0 / ×1.3），但这是用户自选的现实难度 |
| 完成时间（早起 vs 深夜） | ✅ 仅"晨星"额外 +20（真实稀缺行为） |

**为什么没有连续天数加成**：连续加成会把"断一天"的代价放大到"损失未来收益"，这是最典型的流失机制。**改为"总量与趋势"激励**：用户看到的是"本月 47 次"，而不是"连续 12 天"。

## 六、RC 与知识卡的关系

| 概念 | 说明 |
|---|---|
| RC（研究成果） | 数值，累计。用于**集册进度**与"观测台"的回收率统计 |
| 知识卡 | 内容实体。获取规则见 [06 §一](06-知识内容与彩蛋系统.md) |
| 关系 | RC 达到卡池阈值 → 提高**下一张卡的稀有度上限**，但不保证出稀有 |

| 累计 RC | 卡池上限 | 效果 |
|---|---|---|
| 0–99 | T0–T1 | 入门卡 |
| 100–299 | T0–T2 | 常规卡 |
| 300–699 | T0–T3 | 可出稀有 |
| 700–1499 | T0–T3，T3 权重 ×1.5 | 稀有略增 |
| 1500+ | T0–T3，T3 权重 ×2 | 长线用户 |

**为什么不用 RC 直接兑换卡**：兑换会让用户"用时间换知识"，知识变成商品；而**随机+序列解锁**让它保持"意外收获"的属性。用户想要的卡永远可以通过"多完成几次"获得（保底机制见 06 §四）。

## 七、扰动（随机）的数值边界

| 层 | 名字 | 概率 | 数值影响 | 上限 |
|---|---|---|---|---|
| T1 | 微光 | 60% | 无（纯视觉/一句文案） | — |
| T2 | 尘暴 | 25% | XP +10%（当日） | 当日 ≤ 1 次 |
| T3 | 极光 | 12% | XP +20% + 必出 1 张卡 | 当周 ≤ 3 次 |
| T4 | 彗星 | 3% | XP +50%（当日）+ 稀有卡（T3 保底） | 每月 ≤ 2 次 |

**三条约束**：

1. **加成永远是"当日"，永不累计成乘算叠加**；同日多触发时只取最高值。
2. **加成不追溯**：不会因为 T4 就把过去一周的 XP 补上。
3. **加成总额上限**：单月扰动加成 ≤ 当月 XP 的 **8%**（超过则后续 roll 降级为 T1）。这条防止重随机用户与其他用户的进度差距被随机放大。

## 八、周报与趋势（数值怎么被讲出来）

| 指标 | 定义 | 呈现 |
|---|---|---|
| 本周执行次数 | 成功 Session 计数 | 「本周 9 次」 |
| 本周航时 | 成功分钟合计 | 「共 227 分钟」 |
| 达标率 | 达标 / 计划应执行 | 「达标 7 / 应做 9」 |
| 计划休整 | 用户主动设的休息日 | 单列，**不计入漏** |
| 前后对照 | 4 周前 vs 现在 | 「4 周前每周 8 次 → 现在 18 次」 |
| 机构对照 | 各机构完成率 | 只呈现数值，**不做排名、不做"最好/最差"** |
| 累计 | 历史总数 | 「累计 148 次 · 无删除」 |

**呈现红线**：所有句子必须是陈述句。禁出现「你真棒」「继续加油」「超过 xx% 指挥官」「退步了」。

## 九、附录 A：可复算的公式与脚本

```js
// 等级曲线
const gap = (n) => 240 + 40 * (n - 1);                  // 本级所需（在 Lv.n 时）
const T = (n) => { let s = 0; for (let k = 1; k < n; k++) s += gap(k); return s; }; // 累计门槛

// 单次点火 XP
const XP_IGNITE = (minutes, ratio, tier = 1.0) => {
  const base = Math.round(1.6 * minutes);
  const k = ratio >= 1 ? 1 : ratio >= 0.6 ? 0.6 : 0.3;
  return Math.round(base * k * tier);
};

// 同日递减
const DECAY = [1, 0.8, 0.6, 0.4, 0.3, 0.2];
const decay = (n) => DECAY[Math.min(n - 1, DECAY.length - 1)];

// 校验：五类画像的到级周数
const WEEKLY = { light: 280, standard: 546, window: 616, heavy: 784, sprint: 1393 };
for (const [k, w] of Object.entries(WEEKLY))
  console.log(k, { lv3: (T(3) / w).toFixed(1), lv10: (T(10) / w).toFixed(1), lv30: (T(30) / w).toFixed(1) });
```

输出（实测）：

```
light    { lv3: '1.9', lv10: '12.9', lv30: '82.9' }
standard { lv3: '1.0', lv10: '6.6',  lv30: '42.5' }
window   { lv3: '0.8', lv10: '5.8',  lv30: '37.7' }
heavy    { lv3: '0.7', lv10: '4.6',  lv30: '29.6' }
sprint   { lv3: '0.4', lv10: '2.6',  lv30: '16.7' }
```

## 附录 B：待调的旋钮（第一轮内测后按序调）

| 优先级 | 旋钮 | 现在值 | 调整信号 |
|---|---|---|---|
| 1 | `gap` 基数 | 240 | 首周没到 Lv.3 → 降到 200 |
| 2 | 递减序列 | 1/.8/.6/.4/.3/.2 | 重度用户周产出被压太低（<400）→ 放缓 |
| 3 | 窗口 XP | 30 | 早起完成率 <55% → 提到 40（用奖励换真实度，注意别变成"为了奖励早起"） |
| 4 | 难度档系数 | .8/1.0/1.3 | 深空档使用率 <5% → 提到 1.5 |
| 5 | 扰动月上限 | 8% | 重随机用户进度离散度 > 25% → 降到 5% |
