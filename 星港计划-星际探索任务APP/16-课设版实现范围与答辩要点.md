# 16 · 课设版实现范围与答辩要点

> **前提**：这是课程设计作业，不是要上线的产品。目标是**演示时跑得顺、看着像回事、讲得出为什么**。
> 本文把 [15 章](15-顶部三维渲染可行性评估.md) 按「课设尺度」砍了一遍——15 章保留作"如果真要做产品"的依据，答辩时可以拿它证明"我知道生产级要考虑什么"。

---

## 一、一句话结论

**做一个单文件 HTML 演示页就够。** 不用 Unity、不用 Godot、不用 WebView 嵌入、不用打包构建。
浏览器打开 → 星球在转、设施在亮、切标签有反应、按 D 能看到帧率。**这就是课设需要的全部三维。**

已验证可跑：`demo/主页面三维演示.html`（226 行脚本，已过语法检查，无外部资源依赖）。

## 二、做什么 / 不做什么

| 维度 | 课设要做 | 课设不做（15 章里的生产级项） |
|---|---|---|
| 交付形态 | ① Figma 高保真原型（已有 13 版面）<br>② 一个可跑的 HTML 演示页<br>③ 策划文档（已有 16 份） | 上架包、真机发布、App 内嵌 WebView |
| 三维 | 星球自转 + 昼夜光照 + 8 座设施 + 星点背景 + 点击切标签 | 交互式旋转/缩放、LOD 切换、Instancing 合批、后处理、粒子 |
| 昼夜 | 一个方向光缓慢移动，模拟晨昏线 | 真实天文算法（经纬度+日出日落）、六相位主题切换 |
| 设备 | **只在你演示用的那一台电脑上跑顺** | 6 机型矩阵、内存预算、耗电、温升降频 |
| 性能 | 帧率 ≥ 50fps（桌面浏览器，基本无压力） | p95 埋点、G3 内存门、G4 耗电门 |
| 工程 | 单文件 HTML + 一个本地 three.bundle.js，**双击即开、零联网** | 上下文丢失恢复、预热、占位图切换 |
| 资源 | **程序化生成贴图**（零美术资源） | 2048² KTX2 贴图、8 个 GLB 模型、Draco 压缩 |
| 彩蛋 | 无 | 扰动四层、知识卡掉落、命名权 |

**为什么"程序化贴图"是课设的关键简化**：不需要你现在去画/买星球贴图和建筑模型，脚本里用 canvas 随机画海陆+极冠，8 座设施用 Box 几何体。**看起来像一颗星球，成本为零，还不会因为资源缺失而跑不起来。**

## 三、验收口径（课设版，就 4 条）

1. 打开演示页，**3 秒内**星球转起来，不黑屏、不报错
2. 帧率 **≥ 50fps**（按 D 面板实测），演示 5 分钟不卡顿
3. 点「计划 / 任务 / 基地」三个标签，下方内容跟着换
4. 答辩时能指着 D 面板说出：这是什么后端、三角面多少、每帧多少毫秒

> 满足这 4 条，三维部分就可以定稿了。**不需要更严格。**

## 六、答辩要点（技术选型怎么讲）

### 6.1 为什么不用 Unity / Godot（这是必被问的）

> "我们的三维只有顶部 **358×180** 的一块视口，稳态 **3.2 万三角面**。
> Unity 最小包 30–60 MB、Godot 15–25 MB，**为了一个占屏 20% 的星球视窗付这个代价不划算**。
> 而 Web 方案三维部分只有约 3.2 MB，且能直接嵌进原型演示。"

配套数据（都在 15 章 §三、§五）：三角面 32,196 / GPU 单帧 0.35–0.93 ms / 每帧总预算 2.0–5.5 ms。

### 6.2 为什么用 WebGL2 而不是 WebGPU

> "WebGPU 的优势在大量 draw call、compute shader、多线程提交，**本案只需要 ~20 个 draw call、无粒子、无后处理，这些优势一个都用不上**。
> 而且 WebGPU 覆盖有洞：iOS 18 及以下没有，Android WebView 默认开启还得实测。
> 所以基线用 WebGL2（覆盖 >99%），**留了 WebGPU 切换口但不作为依赖**——这也正是产品设计里'不把可选技术放进验收门'的同一原则。"

演示页里按 **W** 键可以现场试切 WebGPU，切失败会自动回退 —— **现场演示这个动作本身就是加分项**（说明你考虑过降级）。

### 6.3 主动说明"哪些是刻意简化的"（比被问出来强）

| 简化 | 说法 |
|---|---|
| 程序化贴图代替美术资源 | "课设阶段用 canvas 随机生成海陆形状，避免资源依赖；正式做会换成手工贴图 + KTX2 压缩" |
| 单方向光代替真实天文算法 | "光照目前是示意性晨昏线；正式版会接经纬度+日出日落计算，误差目标 ≤15 分钟" |
| 无 LOD / Instancing | "3.2 万面在桌面端是余量充足的，LOD 是为移动端低端机准备的，不在课设范围" |
| 固定 8 座设施 | "设施数量和形制在文档里已定为 8 形制 × 5 级，演示只做形制示意" |

### 6.4 可以讲的一处"设计一致性"

> "我们把'不把随机/可选机制放进验收门'这条产品原则，也用在了技术选型上：WebGPU 是可选加速，不进验收；降级路径（预渲染视频）始终可用。**这和技术方案里的 fail-safe 是同一套思路。**"
