# 07 · 三维视窗

## 一、定位与结论
三维是主页面**顶部的一块视窗**，不是全屏三维地图：星球只占顶部一条，页面主体仍是任务、计划与养成。
技术选型 **three.js + WebGL2**；单文件 `demo/主页面三维演示.html` + 本地 `three.bundle.js`，双击即开、零联网、零美术资源。
已实现并在 demo 跑通：16 色像素化管线、globe / focus 双模相机、拖动 / 双指缩放 / 点击聚焦 / Esc 全套输入；实测纯三维区板内率 100%，帧时间 p50 16.4 ms，28 项自动化交互与相机测试全部通过。
取舍：信息量优先于画质；不做自由相机与 LOD 切换；像素风与 UI 共用同一套 16 色，不是给三维加滤镜。

## 二、视窗规格
设计稿按内容区 **358×180** 绘制；实现把画布改成**满幅无界** **390×227**（左右各 16px 边距、顶部 47px 状态栏不再让出），渲染倍率 2 得 **780×454**，状态栏与标题改以浮层压在画布上。

| 项 | 值 | 说明 |
|---|---|---|
| 设计稿内容区 | 358×180 | 顶部固定视窗，占屏 19.6%（可行性评估阶段的基线） |
| 实现视窗 / 画布 | 390×227 / 780×454 | 满幅无界、无 border 无圆角；渲染倍率固定 `SCALE = 2` |
| 大像素边长档 | 键 2 / 3 / 4 / 6 | 键位 = 大像素边长本身（设备 px），默认键 3 |
| DPR 封顶 | 2.0 | 小视窗用 DPR 3 的像素收益远小于耗电代价 |
| 顶部安全区 | 47px | 状态栏 39 + 上边距 8，星球必须让开 |

## 四、像素化三步管线
顺序不可换：先降分辨率决定"块多大"，再量化决定"块什么色"，最后放大只负责硬边。

| 步 | 做法 | 关键参数 |
|---|---|---|
| ① 降分辨率渲染 | 场景渲染到低分辨率 RenderTarget，尺寸 = `drawingBuffer / 大像素边长` | 780×454 ÷ 3 = 260×151；`NearestFilter`（min + mag）；无 MSAA；`depthBuffer: true` |
| ② 色彩量化 | 全屏后处理：按格心取样 → sRGB 空间 Bayer 4×4 抖动 → 与 16 色板取最近色 | 格心 `(cell + 0.5) / uGrid`；抖动强度 0.06；加权 RGB 距离 `(0.30, 0.59, 0.11)` |
| ③ 最近邻放大 | RT 用 Nearest 采样，CSS 再补 `image-rendering: pixelated` 双保险 | 画布 CSS 尺寸必须是整数倍且无 border |

三条实测踩出来的约束：抖动与量化必须在 **sRGB** 空间（linear 下 16 阶里 12 阶分给亮部，夜面深色阶从 5 个塌到 2 个）；抖动坐标用格号 `cell` 而非 `gl_FragCoord`（否则放大后一块里碎成 16 个深浅点）；输出必须**直接是 sRGB**（`ShaderMaterial` 不会被 three 自动套 `outputColorSpace`，再转一次全屏压暗，实测板内率只有 59.5%）。

## 六、布局约束（前提：画布 CSS 尺寸与 RT 格数必须保持整数倍关系）
| 问题 | 现象 | 修法 |
|---|---|---|
| border 占内容区 | `358px + 1px border` → 内容区只有 356px，716 塞进 712 非整数缩放 | 用 `inset box-shadow` 或 `outline` 画描边 |
| 圆角 | `border-radius` 四角抗锯齿混出 `#07090F` 类板外色（984 个板外像素里 424 个贴边） | 像素化时 `border-radius: 0`（= 组件库 `radius/none`） |
| 半透明叠层 | 柔光 / 渐变盖在画布上 → 整屏变板外色 | 像素化时 `display: none`（关柔光后板内率 99.62% → 100%） |

## 七、相机系统
只有两种模式加一个过渡态，不做自由相机："自由相机 + 防穿模 + 边界约束"会让调试成本翻倍，而两模式已覆盖"看全局"与"看一处"。

| 状态 | 触发 | 表现 | 退出 |
|---|---|---|---|
| `globe` / `idle` | 默认 | 全景待机；2 秒无操作启动自转，可拖动、可缩放 | 点中建筑 → `transit` |
| `transit` | 点中建筑 | 1350ms 过渡，期间不接受输入 | 到达 `focus` |
| `focus` | 过渡结束 | 以建筑为球心环绕，天空 ≈1/3、建筑在下三分之一 | Esc / 点空白 → `transit` |

**`globe` 全景机位**：球面轨道相机，位置由距离 + 俯角决定，`pos = (0, sin(el)·d, cos(el)·d)`、`lookAt(0,0,0)`、`up = (0,1,0)`。

| 参数 | 值 |
|---|---|
| 距离 | 2.80 – 5.60 R，默认 3.60（球角直径 32.3°、占屏高 92%，完整可见且够大） |
| 俯角 | 4° – 58°，默认 18° |
| 待机自转 | 0.0831 rad/s（≈76 s 一圈，实测），惯性每帧 ×0.92 |
| 顶部让位 | 视线抬升 α 让星球下移；7 档实测顶端 y = 48.0 – 70.5 px，全部 ≥ 安全线 47，与面板预测差 ≤1px |

**`focus` 聚焦机位**：**以建筑为球心的第二层轨道**。取建筑处局部正交基（径向 n / 北切向 tN / 东向 tE），把实测校正过的 home 机位换算成相对建筑的偏移 `off = home − P`（`P = n · 1.0`），分解为球坐标 `(r, θ₀, φ₀)`，再叠加拖动量：`θ = clamp(θ₀ + fPol, 22°, θmax)`、`φ = φ₀ + fAz`、`r' = r · S.dist / FAC.dist`；`fAz = fPol = 0` 时与原 home 机位数学上完全一致。

| 参数 | 值 |
|---|---|
| dist | 1.10 R；实测天空 35.9%、建筑 x=50.0% / y=68.2%、可点面积约 1,900 px |
| back / pitch | 0.19 R / +8°（把建筑压到画面下三分之一） |
| 缩放范围 | 1.03 – 1.80 R |
| 枢轴半径 | 1.0 R（用设施的 1.006 会让建筑屏位从 68.2% 漂到 72.3%） |
| 极角夹取 | θ ∈ [22°, θmax]；θmax 按当前 r 反解，使相机半径 ≥ 1.05 R，不钻 1.035R 大气壳 |
| 上方向 | `camera.up` 取该点径向 n，不用世界 +Y（否则地平线左高右低，中央区差 40px / 8.8%） |

**过渡规则**：1350ms（实测 1.32–1.34 s），四条时间线错开重叠：位置 0–1、距离 0.04–0.80、up 0.02–0.62、看点 0.10–0.98；缓动 `cubic-bezier(.42,0,.58,1)`，峰值 / 平均 1.724；角位移与半径变化的显著区间**重叠 58%**，"绕过去"与"降下去"是一个连续动作。
路径是**贴着球面的螺旋**：方向 slerp、半径线性插值 + 中段抬升 `FLY_LIFT = 0.05`，取螺旋 1/3、2/3 处为三次贝塞尔控制点，路径向远离球心一侧外弓（最近 7.7% / 最远 14.9% 弦长），最小半径 1.1001 / 1.1005 R，不钻 1.035R 大气壳。

## 八、输入处理
只用 Pointer Events 一套（`pointerdown / move / up / cancel` + `pointerId`），同时覆盖鼠标、触摸、手写笔。

| 输入 | 处理 |
|---|---|
| 单指拖动（globe） | 横拖改 `S.spin`，灵敏度 0.006 rad/px（拖 120px = 0.727 rad）；纵拖改俯角 `S.el`，范围 4°–58° |
| 双指缩放 | `k = 初始间距 / 当前间距`，`S.dist = clamp(初始距离 × k, 2.80, 5.60)`；用初始距离 × 比例而非累乘，避免浮点漂移 |
| 点击聚焦 | 位移 > 6px 即判为拖动；抬起且未拖动才当点击；拾取 = 精确射线 + 屏幕距离 < 20px 兜底 |
| 聚焦态拖动 | 横拖改 `S.fAz`，**−**×0.008 rad/px（满屏 390px ≈ 3.12 rad ≈ 179°，负号 = 转头手感，内容左移）；纵拖改 `S.fPol`，×0.004 rad/px（往下拖 = 相机升高） |
| Esc | 退出聚焦，回到 `globe` |

建筑在任何方位角都钉在同一屏幕位置（转 4.48 rad ≈ 257° 后仍 x=50.0% / y=68.2%），相机↔枢轴半径恒定 0.2185 R。

## 九、光照与昼夜（简化保留）
课设只做**示意性晨昏线**：一个方向光 + 六相位色，不接真实天文算法（经纬度、日出日落）。

| 相位 | 判据（当地真太阳高度角） | 表现 |
|---|---|---|
| 晨 `dawn` | −6° → 0° | 半球偏冷蓝，边缘金橙，星渐隐 |
| 昼 `day` | > 0° | 全面亮，设施灯光关闭，星空不可见 |
| 昏 `dusk` | 0° → −6° | 暖橙压过蓝，长影，星开始出现 |
| 夜 `night` | −6° → −18° | 主色深蓝，设施成为唯一光源，银河清晰 |
| 深夜 `deep` | < −18° | 极暗，仅有设施灯与测绘线 |
| 极昼 / 极夜 `polar` | 高纬度季节性 | 全天不切换昼夜；极昼时星空为稀薄蓝 |

## 十一、技术选型结论
| 决策 | 结论 | 依据 |
|---|---|---|
| 引擎 | three.js + WebGL2，不用 Unity / Godot | 包体 Unity 30–60 MB、Godot 15–25 MB，而三维资源合计仅 3.2 MB |
| WebGPU | 不做，只留切换口 | 覆盖有洞（iOS 18 及以下没有、Android WebView 待实测）；本案 ~20 draw call、无粒子、无后处理，WebGPU 的优势一个都用不上 |
| 资源 / 交付 | 三维部分 ≈ 3.2 MB；单文件 HTML + 本地 `three.bundle.js`，双击即开、零联网、零构建 | three.js 0.17 + 应用逻辑 0.30 + 贴图 KTX2 1.5 + 设施 GLB 1.2 |

## 十二、已知限制
| # | 限制 | 说明 |
|---|---|---|
| 1 | WebGPU 路径不启用像素化 | `ShaderMaterial` 后处理需改写成 TSL；WebGPU 本就不进验收，故直接提示"未启用" |
| 2 | 色板固定 16 色，不随相位切换 | 晨 / 昼 / 昏 / 夜四相位色已塞进同一套；要换色板需拆成 4 套（各 8–10 色）并做淡入过渡 |
| 3 | 抖动强度固定 0.06 | 若某档位露色带，可提到 0.10–0.12 |
| 4 | `focus` 环绕时星球不自转 | 环绕靠移动相机实现，星球须静止，否则建筑会跑出视锥 |
| 5 | 聚焦态无"回 home 机位"手势、无点击涟漪 / 高亮反馈；建筑是盒体占位 | 退出再进才复位；选中态只有视角切换；枢轴不跟随建筑 LOD 缩放，聚焦时从 3.2× 缩回 1× 有跳变（设施形制见 04-数值与养成.md） |
| 6 | 惯性只是每帧 ×0.92 的指数衰减；未做双指旋转 | 无"松手速度 → 位移"映射；已加 `touch-action: none`，页面若改成可滚动需重验手势归属 |
| 7 | 过渡期间 1350ms 点按会被丢掉；过渡曲线与时间窗是文件顶部常量 | 顶部安全区硬编码 47px，改 CSS 需同步 `SAFE_TOP` |

## 十三、答辩要点
- **为什么不用 Unity / Godot**：三维只有顶部一块占屏约 20% 的视窗、稳态 6,272 面；为这块星球付 30–60 MB 包体不划算，Web 方案三维部分只有 3.2 MB，还能直接嵌进原型演示。
- **为什么是 WebGL2 而不是 WebGPU**：WebGPU 的优势在大量 draw call、compute shader、多线程提交，本案 ~20 个 draw call、无粒子、无后处理，一个都用不上；且覆盖有洞（iOS 18 及以下没有），所以留切换口但不进验收。
- **像素化不是加滤镜**：把渲染分辨率降到 1/16 再量化到项目 16 色板，实测纯三维区 100% 的像素精确落在 16 色内、无插值过渡色；因为渲染量降到 1/16，开了反而更快。
- **相机是有状态的地图**：1350ms 内四条时间线重叠推进，贴着球面的螺旋飞入，最小半径 1.1001R 不钻大气壳；峰值速度从 6.1 R/s 降到 3.4 R/s 靠的是修掉三个把缓动拧坏的陷阱，不是"看着不顺眼就加时长"。
