# NES 菜单套件 · 12px 版

**目标**：只要 **NES 风格的菜单 UI**，沿用之前那套「NES 8-BIT」的视觉语言，字体用 **12px 并对齐网格** —— 从而**省掉「字体转矢量」那一步**。

**产物**：`nes12-menu-kit.figcraft`（可编辑）/ `.fig` / `assets/`（22 张 PNG）/ `sheet-1x.png` `sheet-2x.png` / `manifest.json`。

---

## 1. 这一版最关键的一点：标签是**真 TEXT 层**，不用转图形

之前的 10px 套件把每个字用 GDI 栅格化成点阵、再逐格画成方形 path（因为 FigCraft 文本渲染恒带抗锯齿）。代价是按钮文案**无法**通过组件属性替换。

这次实测发现：**`Ark Pixel 12px Mono zh-Hans` @12px 在 FigCraft 里渲染是纯二值的**。

```
孤立测试：TEXT 层 @12px → 截图色数 = 2（#000000 / #ffffff），零过渡色
```

所以这一版直接建 TEXT 层，而且能绑成组件属性：

```
component.addProperty { id, name:'Label', type:'text', layer:<TEXT层的id>, default:'开始游戏' }
→ {"default":"开始游戏","name":"Label","type":"text"}

component.properties { id: 实例id }
→ [{"default":"开始游戏","name":"Label","type":"text","value":"读取存档"}]
```

**并且覆盖是真的重绘像素**（不是只存属性）：同一组件的两个实例，一个默认文案、一个改成「读取存档」，逐像素比对：

```
两图不同像素 = 257
差异区域: x 0..46  y 7..17   (47×11)
```

差异区正好是文字墨迹带（y 7..17 = 墨点范围），宽度差 47 对应 `开始游戏` 与 `读取存档` 的字宽差。

**这带来的实际收益**：改按钮文案只要改实例属性，不用碰字模、不用重建。

## 2. 网格对齐（全部实测，无估算）

`Ark Pixel 12px Mono zh-Hans` 在 12px 下的度量：

| 项目 | 实测值 |
|---|---|
| 汉字 / 全角标点 / 箭头 推进宽度 | **12 px** |
| 拉丁字母 / 数字 / 半角空格 推进宽度 | **6 px** |
| TEXT 节点高度 | **12 px** |
| 墨点纵向范围 | 节点顶 **+1 … +11**（11 行） |
| 行距 | **12 px** |

宽度实测样本：

```
"开"=12   "开开"=24   "开始游戏"=48   "开始游戏开始游戏"=96
"A"=6     "AB"=12     "ABC"=18       "A1"=12
"中 文"=30   "↑"=12   "↑↓"=24        "，"=12
```

**每个标签宽度都是整数**，所以按钮/行的宽度全部由实测字宽反推，没有任何取整误差：

- 按钮默认 **128×24** = `左右各 16` + `96`（8 个汉字）；高 24 = `上下各 6` + `12` 字高
- 列表行高 **20** = `上下各 4` + `12`
- 菜单窗宽度 = `18`(左内边距) + 最长标签 + `12`(间距) + 最长快捷键 + `8`(右内边距)

放置精度验证：同一文本放在 y=0 与 y=20，墨点带分别落在 `1..11` 和 `21..31` —— 间距**正好 20**，零漂移。

## 3. 面板与自检结果

| 页 | 内容 |
|---|---|
| **COMPONENTS** | 按钮变体集 `Btn · NES 12`（4 个变体 + `Label` 文本属性）。**独立页**，见第 5 节 |
| **BUTTONS** | 4 态预览（128×24）+ 4 个实例演示「只换 Label 属性改文案」 |
| **LIST & MENU** | 列表行（选中金底+▶+右对齐快捷键）/ 菜单窗（标题条+行+底部提示）/ 消息窗（名牌+两行正文+▼） |
| **FORM** | 开关 / 复选 / 单选 / ◀值▶ 取值箭头 |
| **SCREENS** | 标题菜单 / 暂停菜单 / 设置菜单 / 物品列表 / 对话场景（各 256×240） |

**版面自检（`audit.mjs`，判据全为几何量）**

```
BUTTONS      BUTTON · 按钮 4 态    余 L-8 T-8 R-8 B-8    零越界
BUTTONS      INSTANCE · 实例改文案   余 L-8 T-8 R-8 B-8
LIST & MENU  ROW · 列表行          余 L-8 T-8 R-8 B-8
LIST & MENU  MENU · 菜单窗         余 L-8 T-8 R-8 B-8
LIST & MENU  DIALOG · 消息窗       余 L-8 T-8 R-8 B-8
FORM         FORM · 表单控件        余 L-8 T-8 R-8 B-8
SCREENS      TITLE / PAUSE / OPTIONS / ITEMS / DIALOG  全部 256×240，零越界

=== 零越界 / 零重叠 / 全整数坐标 ===
```

（`L-8 T-8 R-8 B-8` 的负号是 `PAD=8` 的固定内边距，五张卡片完全一致 = 内容与卡框严格对称贴合。）

**像素纯度（逐卡片 1:1 截图，逐像素比对调色板）**

```
零板外色的卡片：6 / 11   （BUTTONS×2、ROW、FORM、TITLE、OPTIONS）
板外像素合计：600 / 705840 = 0.085%
其中邻近文字色的比例：ITEMS 100%、MENU 63%、DIALOG 60%
```

那 0.085% 是 **FigCraft 文本光栅器在个别字形边缘产生的过渡像素**，集中在金/白字压在深底的强对比边缘上，不是设计缺陷：

- 6 张卡片**精确为 0%**
- 有残留的 4 张里，像素位置全部落在文字墨迹带内（ITEMS 达 100% 邻近文字）
- 总量 600 像素 ≈ 一个 24×25 的方块，占全图万分之八

`manifest.json` 每条记录 `offPalettePx` 与 `offNearText`，可直接复核。

## 4. 修掉的真实缺陷（都有数值证据）

| 缺陷 | 证据 | 修法 |
|---|---|---|
| 标题菜单底部溢出 2px | 菜单窗 `[200..292]` 超出屏底 282 | 菜单顶从 y=158 移到 y=128 |
| 版权行/提示行右侧溢出 48px / 69px | 节点 `[8..320]` 超出卡 `0..272` | `t()` 的节点宽度改为**实测字宽**，不再声明成整个参考框 |
| 按钮卡出现 510 个紫色像素（`#9747ff` 等 8 色） | y=22 一整条 113px 宽带 | 组件集搬到独立页（见第 5 节） |
| 4 个实例压在别的卡片上 | 实例 absoluteBounds `[8..136]`，在页原点 | `instance.create` 后必须 `node.reparent` 进卡片 |

---

## 5. 组件集必须放独立页（实测结论）

`component.combineVariants` 合并变体后：

1. 组件集会被挪进**自己的坐标系**（实测落在负 x：`COMPONENT_SET "Btn · NES 12" [-12..156]x[22..206]`），原来的 4×40 网格布局被打破；
2. 组件节点会带 **FigCraft 的组件外框色**渲染进截图 —— 实测在按钮卡里产生 510 个紫色像素，颜色是 `#9747ff / #9748ff / #9a4aff / #9054e0 …` 这 8 个板外色，且在 y=22 连成一整条 113px 的带。

把组件集搬到 `COMPONENTS` 独立页后，按钮卡板外色从 **510 → 0**。

## 6. 文件结构

| 路径 | 说明 |
|---|---|
| `nes12/core.mjs` | 调色板（沿用旧 NES 8-BIT 色值）、几何原语（`rect/ring/cells`）、光标与箭头点阵、**字宽实测表** `textWidth()` |
| `nes12/widgets.mjs` | `t()`（真 TEXT 层）、`win()`、`bevel()`、`button()`（4 态）、`row()`、`menu()`、`dialog()`、`toggle/checkbox/radio/stepper/optRow` |
| `nes12/build.mjs` | 构建 6 个页面 |
| `nes12/export-assets.mjs` | 导出 1x/8x PNG + `manifest.json` + 纯度判定 |
| `nes12/audit.mjs` | 越界 / 重叠 / 整数坐标 / 像素纯度自检 |
| `nes12/sheet.mjs` | 总览图（纯 Node 编解码 PNG，无依赖） |
| `nes12/render.mjs` | 逐页整页截图 |

```bash
cd figcraft_mcp/pixel/nes12
node build.mjs           # 重建
node export-assets.mjs   # 导出资产
node audit.mjs           # 自检
node sheet.mjs           # 总览图
node render.mjs          # 整页截图
```

## 7. 与 8px/10px 旧版的差异

| | 旧 10px 套件 | **本版 12px** |
|---|---|---|
| 放大倍率 | 4 设计像素 = 1 游戏像素（画布放大 4 倍） | **1 设计像素 = 1 游戏像素**（画布即 256×240） |
| 标签实现 | 字体 → 点阵 → 逐格方形 path | **真 TEXT 层** |
| 改文案 | 必须改字模重建 | **改实例属性即可**（已验证像素重绘） |
| 按钮状态 | 7 态 | **4 态**（default / hover / active / disabled） |
| 范围 | 6 种风格 × 5 态 + 面板 + 完整画面 | **只做菜单**：按钮、列表、菜单窗、对话框、表单控件 + 5 个画面 |

## 8. 已知限制

1. **只有 4 个按钮状态**。如需 focus / selected / danger，在 `widgets.mjs` 的 `btnStyle()` 里加分支即可（每个状态给一组 `{body,hi,lo,fg}`）。
2. `active` 态是**金底黑字 + 内容下移 1px**。如果只想要颜色变化，把 `press` 改成 0。
3. **调色板只有 25 色**（沿用旧套件）。要加色请在 `core.mjs` 的 `P` 里加，并同步更新 `audit.mjs` / `export-assets.mjs` 里的 `PALETTE` 集合，否则自检会误报。
4. 0.085% 的文字边缘过渡像素是 **FigCraft 渲染器的行为**，无法从设计侧消除；`manifest.json` 里逐卡记录了数值。
5. 字体 **Ark Pixel 12px Mono zh-Hans**（OFL 1.1），需本机已安装；FigCraft 通过 `text.fonts` 读取系统字体。
