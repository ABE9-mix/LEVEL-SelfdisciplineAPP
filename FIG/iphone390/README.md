# iPhone 390 线框模板 · LEVEL

**用途**：给 LEVEL（游戏化自律 App）做界面宽框（wireframe）初稿。390 × 844 是 iPhone 14 / 15 / 16 的逻辑分辨率，所有控件都按这个宽度实测量过，可以直接拖用。

**一句话**：`iphone390-wireframe.figcraft` 里是 **1 个封面 + 1 个组件页 + 1 个基元页 + 12 个 390×844 的屏**；屏上每个控件都是组件实例或组件里的图层，改组件 → 12 屏同步变。

## 3. 线框语言（为什么只有灰）

- **只用 9 个灰**：`#181B20`（一级文字、实心按钮、选中态）、`#5A5C60`（二级文字）、`#8B8D90`（三级文字、图标）、`#B4B6B9`（图片/图标占位块）、`#DCDFE4`（槽、骨架、未填进度）、`#E2E4E8`（分隔线）、`#C9CDD4`（控件描边）、`#FFFFFF`（卡片底）、`#F4F5F7`（页面底）。
- **实线 = 已经确定的界面；虚线 = 可选机制或空位**：魂火挑战、风险强度、未解锁徽记、篝火结算、空状态占位全是虚线框。评审时一眼能分清"必须做"和"可选做"。
- **方块 = 图片 / 图标占位**：`24×24` 的方块右上切角，代表 iOS 风格的图标位；`22×22` 圆角块代表列表项缩略图。
- **文字是真 TEXT 层**（不是转成的图形）：改文案直接双击改，换字体只要换 `fontFamily`。
- 这套线框和同目录的 `FIG/nes12` **是两套并列的视觉语言**，不要混用：`nes12` 是最终像素风 UI（256×240、12px 点阵字），本套是 390 宽的结构稿。

## 5. 自检结果（判据全为几何量 / 像素量）

```
共 12 屏 · 节点 886 · 文本层 379
屏尺寸 12/12 = 390×844；2x 导出 12/12 = 780×1688
出屏：0 处超过 2px
非整数坐标：0 处
实质压叠：2 处，均为故意（见下）
设计外色（超出「9 个令牌色 ±24」集合）：0.073%（全部是文字抗锯齿过渡像素）
彩度 > 8/255 的像素：0.179%（最大色度 11/255，即近中性灰的边缘混色）
```

三处需要说明的数值：

1. **"实质压叠 2 处"**：`12 · 弹窗` 里模态卡刻意压住背景任务卡、虚线"失败代价"框刻意压在模态卡内 —— 这就是模态该有的样子，不是缺陷。判据里已经把"卡片 vs 卡内控件、叠加态控件、遮罩 vs 内容"排除掉了。
2. **`headless 实例底色 #000000`（5.9% 像素）**：headless 渲染时组件实例自带黑底，`KIT` 页里放 TabBar / NavBar 实例的地方会出现黑块。**在 FigCraft 界面里打开是正常的**（导出 PNG 里没有黑块，见 `screens/` 与 `sheet-screens.png`）。这条已单列，不混进设计外色。
3. **0.179% 的彩色像素**：文字 PNG 光栅化的抗锯齿会混出 `#35383c`、`#414448` 这类过渡色，最大色度只有 11/255。这是渲染器行为，设计侧无法消除；把灰改成严格中性（例如 `#8A9099 → #8B8D90`）后该值从 0.776% 降到 0.179%。

## 6. 怎么改（三条最常用的路径）

**① 改文案**：双击任意文字层直接改。按钮 / 列表行 / 任务卡的文案都在实例里，改实例不动主组件。

**② 改组件样式**：进 `COMPONENTS` 页改主组件（比如按钮圆角、卡片描边色），12 个屏里的实例同步更新。

**③ 换配色 / 字号 / 间距**：改脚本目录下的 `core.mjs`：

```js
export const G = { canvas:'#F4F5F7', surface:'#FFFFFF', line:'#E2E4E8', edge:'#C9CDD4',
                   ph:'#B4B6B9', ph2:'#DCDFE4', ink3:'#8B8D90', ink2:'#5A5C60', ink1:'#181B20', white:'#FFFFFF' }
export const FS = { display:28, title:20, nav:17, body:15, sub:13, cap:11 }
export const M = { side:16, cardPad:14, navH:44 }   // side = 左右安全边距，CONTENT_W 自动跟着算
```

然后按顺序重跑：

```bash
cd F:/deepseek/作业/figcraft_mcp/pixel/iphone390
node build.mjs         # 重建 15 个页面（含组件页）
node kit-fix.mjs       # KIT 页按内容实测高度重排
node render.mjs        # 逐帧 1:1 截图 + 整页图
node audit.mjs         # 自检（越界/压叠/坐标/像素）
node export-assets.mjs # 导出 1x/2x PNG + manifest
node sheet.mjs         # 12 屏总览
node deliver.mjs       # 打包到 LEVEL-app\FIG\iphone390
```

## 7. 已知限制

1. **组件实例的文案是"默认值"，不是每条定制的**。FigCraft 支持 `instance.setProperties` 改组件属性，但本套件是按"整屏装配"的方式生成的——12 屏上的任务卡 / 列表行文案都是直接建成文字层，不是实例。这样做的好处是每屏文案可独立改；代价是改主组件不会改文案（改样式、改结构会）。
2. **无滚动条示意**。线框里没有画滚动指示，长列表屏（如 10 成长记录）默认视为可滚动，若需要可加一根 4px 灰条。
3. **没有画真实图标**。图标一律是"切角方块"占位，正式稿需要替换为 24×24 的线性图标。
4. **状态栏是手画的**（9:41 + 信号 + WiFi + 电池），不含灵动岛 / 刘海。若要演示机壳，可在外面套一个 390×844 的圆角遮罩。
5. **字体依赖本机 MiSans**。换机器打开若缺字体，会回落到系统无衬线；度量会略有偏移（中文按 13px ≈ 13px 估宽，英文按 7px）。

## 8. 与 `FIG/nes12` 的关系

同一产品的两种表达：

| | `FIG/nes12` | **本套 `FIG/iphone390`** |
|---|---|---|
| 尺寸 | 256×240（NES 原生） | 390×844（iPhone 逻辑分辨率） |
| 阶段 | 最终视觉（像素风 UI） | **前期结构稿（线框）** |
| 颜色 | 25 色 NES 调色板 | 9 级中性灰 |
| 字体 | Ark Pixel 12px（真 TEXT 层） | MiSans 28/20/17/15/13/11 |
| 用途 | 游戏内菜单画面参考 | 信息架构与流程评审 |
